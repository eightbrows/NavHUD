NavHUD ファイル形式

目標針路案内アプリ ・ 20261125-D02 時点 ・ このアプリが読み書きするファイルの説明

1 WP リスト

読み書きできる形式

形式読み込み書き出し入れ方
CSVできるできる起動時の「リストを選ぶ」、または「WP設定」（WP ボタン列の左端の「WP」）→ インポート / エクスポート。インポートはファイルの画面（最近のファイル 5 件・ファイルを選ぶ…）から
GPXできるできないCSV と同じ（インポート）。読むのは <wpt> だけ
座標の文字できる（1点）—「WP設定」→ 貼り付け（クリップボードの 緯度, 経度）、または 追加・編集の入力欄
  • CSV か GPX かは、ファイルの中身で見分けます。先頭が <?xml か <gpx なら GPX、それ以外は CSV です。ファイルの名前や拡張子は見ません。
  • インポートすると、今のリストと置き換わります（足し込みではありません）。
  • WP リストはアプリの中に保存しません。編集したら、エクスポートで CSV に書き出してください。覚えているのは「最後に読み込んだか書き出したファイルの場所」だけで、次の起動のときにそのファイルを読み直します（設定で、起動のたびに選ぶ形にもできます）。
  • 到達済みかどうかは、ファイルに書き出さず、読み込みもしません。

CSV の決まり

見出し行必要です。1行目（空の行を除いた最初の行）を見出しとして読みます。列は見出しの名前で探すので、順番は自由です。知らない名前の列は無視します。大文字・小文字は区別しません。
区切りカンマ（,）だけです。タブやセミコロンは区切りになりません。
文字コードUTF-8（BOM はあってもなくてもよい）。UTF-8 として読めないときは、Shift_JIS（Windows-31J）として読みます。
改行CRLF・LF・CR のどれでも、混ざっていても読めます。空の行は無視します。
値の囲みカンマ・改行・" を含む値は "..." で囲みます。中の " は "" と書きます。囲んでいない値は、前後の空白を取って読みます。
小数点ピリオド（.）です。カンマは区切りになるので使えません。

CSV の列

列の名前意味必須書かなかったとき書き方の例
lat緯度。10進の度で、−90〜90。南緯はマイナス必須その行は読めない行33.46679346
lon経度。10進の度で、−180〜180。西経はマイナス必須その行は読めない行132.96174603
ele標高 [m]。標高プロファイルに使います省略可標高なし（標高プロファイルに点を描かない）1300
name名前。画面の文字と WP ボタンに出ます省略可WP1・WP2…（読めた順の番号）展望台
target_time目標時刻（端末の時刻）。TGT の計算に使います省略可目標時刻なし（TGT は ---）08:30 8:30 8:30:00
deadline_time締切時刻（端末の時刻）。DDL の計算に使います省略可締切時刻なし（DDL は ---）08:45
enabled有効か無効か。無効の WP は目標にせず、グレーの破線で描きます省略可有効1（有効）0（無効）。true / false も可
radiusこの WP だけの到達半径 [m]。0 より大きい数。この半径に入ったら到達にします省略可今の移動のプリセットの到着半径（初期値は自動車 30 m・歩行 15 m）を使う100
  • enabled と radius は、このアプリ独自の列です。ほかの 6 列だけの CSV も、そのまま読めます。
  • 時刻は 時:分 か 時:分:秒 です（時は 0〜23、1桁でもよい）。日付は持ちません。全角の数字・コロンで書いても読めます。0830 や 8時30分 は読めません。
  • radius がある WP では、通過の予備判定の「近づいた距離の上限」も、半径 × 3 の方が大きければそちらを使います。

緯度・経度の書き方

場所読める書き方読めない書き方
CSV の lat・lon の列10進の度を、列を分けて書く。33.46679346、-33.4、+33.4。前後の空白は可度分秒（33°28'00"）、N33.4 のような文字つき、範囲の外の数
貼り付け、追加・編集の入力欄緯度, 経度 を1行で。34.69370, 135.50230（Google マップでコピーした座標の形）。カンマの前後の空白はあってもなくてもよい。符号も可かっこつき、空白だけで区切ったもの、URL、度分秒、2行以上
GPX の <wpt>lat・lon の属性に、10進の度範囲の外の数、数でない値

読めない行があったとき

  • その行だけを飛ばし、読めた行でリストを作ります。読み込みは止まりません。
  • 読み込みのあと、「WP設定」の画面に「○○ から N 件を読み込みました（読めない行 M 件をスキップ）」と出ます。
  • 地図の画面にも、数秒だけ「WP N 件を読み込みました（ファイルの名前）」と出ます。無効の WP があれば「WP N 件（うち無効 M）を読み込みました（…）」です。起動のときに前回のリストを開いたときも出ます。
  • 読めない行になるのは、次のどれかのときです。
    • lat・lon が空、数でない、範囲の外。
    • ele が数でない（空はよい）。
    • target_time・deadline_time の形が違う（空はよい）。
    • enabled が 1・0・true・false・空 のどれでもない。
    • radius が 0 以下、または数でない（空はよい）。
  • 見出し行に lat と lon がないと、すべての行が読めない行になります（見出しのない CSV も同じです）。

サンプル（CSV）

このまま waypoints.csv として保存すれば読み込めます。

lat,lon,ele,name,target_time,deadline_time,enabled,radius
33.47649101,133.00275172,1300,峠の入口,,,1,
33.46679346,132.96174603,,展望台,08:30,08:45,1,
33.48377796,132.87220649,,旧道（通行止め）,,,0,
33.48750794,132.90060923,,道の駅,09:10,09:20,1,100
33.55944388,133.00766313,,ダム,,,1,
33.667743,132.8949383,,終点,11:00,,1,

3行目は無効の WP（enabled が 0）、4行目は到達半径 100 m の WP です。空の欄は「なし」になります。

書き出し（エクスポート）

  • CSV だけです。列は上の 8 列を、この順番で書きます。はじめのファイル名は waypoints.csv です。
  • 文字コードは UTF-8（BOM つき）、改行は CRLF です。Excel でそのまま開けます。
  • 緯度・経度は桁を落とさずに書きます。時刻は 08:30（秒があれば 08:30:15）、enabled は 1 か 0 です。値のない欄は空にします。
  • カンマ・改行・" を含む名前や、前後に空白のある名前は、"..." で囲んで書きます。
  • 書き出した CSV は、そのまま読み込めます（上のサンプルは、書き出したときの形と同じです）。

GPX

読むのは、ファイルの中の <wpt>（ウェイポイント）だけです。<rtept>（ルートの点）と <trkpt>（軌跡の点）は読みません。

GPX の中身WP の項目書かなかったとき・読めないとき
wpt の lat・lon緯度・経度（必須）その <wpt> を飛ばして、件数に数える
<name>名前WP1・WP2…
<ele>標高 [m]標高なし
<time>目標時刻目標時刻なし
<extensions> の <deadline>締切時刻締切時刻なし
  • <time> と <deadline> は、日付つきの時刻（2026-08-13T23:30:00Z の形）なら、端末の時刻帯の時刻に直して使います（日本なら 08:30）。08:45 のように時刻だけを書いてもかまいません。
  • 有効 / 無効と、WP ごとの到達半径は GPX では指定できません。すべて「有効」「全体の設定の半径」になります。
  • XML として読めないファイルは、0 件になります。
<?xml version="1.0" encoding="UTF-8"?>
<gpx version="1.1" creator="example" xmlns="http://www.topografix.com/GPX/1/1">
  <wpt lat="33.46679346" lon="132.96174603">
    <ele>1280</ele>
    <time>2026-08-13T23:30:00Z</time>
    <name>展望台</name>
    <extensions><deadline>08:45</deadline></extensions>
  </wpt>
  <wpt lat="33.48750794" lon="132.90060923">
    <name>道の駅</name>
  </wpt>
</gpx>

2 軌跡（再生用の記録）

REPLAY で再生する記録です。左の列の ⇄ で REPLAY にして、その下の FILE で開くファイルの画面から選びます（最近のファイル 5 件からも開けます）。読めるのは、GpsLogger が記録する track.csv と、GpsLogger で書き出した zip です。書き出しはありません。

GpsLogger の形式そのものの説明は、GpsLogger の説明を見てください: https://github.com/eightbrows/GpsLogger

track.csv でこのアプリが使う列

列の名前意味このアプリでの使い道
latitude緯度 [度]位置（必須）
longitude経度 [度]位置（必須）
epoch_ms時刻（1970 年からのミリ秒）時刻（必須。再生の進み方、TIME、TGT・DDL・ETA の計算）
utc_iso8601時刻（2026-08-13T22:52:35.000Z の形）epoch_ms が読めない行で、代わりに使う
altitude_ellipsoid_m高さ（楕円体高）[m]ALT（海抜高度。Android 14 以上は端末の仕組みで求め、それより前はここから標高オフセットを引く）、V/S（高さの変化）、標高プロファイルの現在地、AGL
speed_mps速度 [m/s]GS、ETA、方位の保持、真横通過の判定、位置から求める向き（TRK）の歩いた距離
bearing_deg進行方位 [度]HDG（GPS の方位）、真横通過の判定
bearing_acc_deg方位の精度 [度]GPS の方位を使うかどうか。0 か空の行は「方位なし」（停止中）として扱う
horizontal_acc_m位置の精度 [m]GPS の方位と、位置から求める向き（TRK）に使うかどうか（設定の位置精度の上限と比べる）。TRK で結ぶ距離（精度が悪いと長くする。最長 15 m）。軌跡のなめらかさ（15 m を超える点は平均に使わない）
elapsed_realtime_ns端末の起動からの経過時間 [ns]歩数（steps.csv）との時刻合わせだけに使う（この下の「歩数」）。列がない・読めない点がある記録では、歩数を使わない
gap_beforetrue = 一時停止からの再開後の最初の点合計の歩数を数える区間の境目だけに使う（この下の「歩数」）。列がない記録は区切らない
  • これ以外の列（provider・gdop など）は読みません。GpsLogger のほかのファイルは、zip のときの steps.csv・meta.json（この下の「歩数」）のほかは読みません（sats.csv・track.gpx・track.kmz）。
  • 1行目は見出しです。列は見出しの名前で探すので、順番が違っても、列が増えていても読めます（名前の大文字・小文字は区別します）。区切りはカンマ、文字コードは UTF-8 です。
  • 緯度・経度・時刻のどれかが読めない行は飛ばします。読める行が1つもないと、「○○ に読める行がありません」と出ます。
  • bearing_acc_deg の列がない記録では、速度が 0 の行を「方位なし」として扱います。
  • 記録の途中の抜け（時刻の間があいた所）は、そのまま再生します。抜けが長いと NO FIX になります。
  • 読み込みのあと、地図の画面に数秒だけ「軌跡 11,172 点・7:52〜11:02（track.csv）」の形で、点の数と、最初と最後の時刻（端末の時刻帯。日をまたぐ記録は日付も）が出ます。zip のときは、ファイルの名前のあとにセッションの名前が付きます。歩数（この下の「歩数」）を使える記録で合計が 1 歩以上なら「軌跡 1,223 点・17:01〜17:21・歩数 2,083 歩（…）」と合計の歩数も出ます。起動のときに前回のファイルを開いたときも出ます。

zip から読むとき

  • GpsLogger で書き出した zip を、そのままファイルの画面で選べます。zip かどうかは、名前ではなくファイルの中身で見分けます。
  • zip の中の session_yyyyMMdd_HHmmss/track.csv を探します。名前が track.csv のファイルなら、フォルダの深さは問いません。選んだセッションの steps.csv・meta.json（この下の「歩数」）のほかのファイル（sats.csv など）は読み飛ばします。
  • zip を開くと、中のセッションの一覧が出ます。セッションが1つだけでも一覧を出します。1つ選ぶと、その記録を再生します。セッションをつないで1本にはしません。
  • 一覧は、開始時刻の新しい順です。1行に、開始時刻（端末の時刻帯）、長さ、点の数、フォルダの名前が出ます。読める行のないセッションは、一覧には出ますが選べません。
  • 選んだ zip とセッションを覚えていて、次の起動では同じセッションを開きます。そのセッションが zip の中に見つからないときは、一覧を出します。
  • zip の中身は、端末に展開しません。必要な track.csv（と同じセッションの steps.csv・meta.json）だけを読みます。
  • 壊れた zip や途中で切れた zip は「zip として読めませんでした」、track.csv の入っていない zip は「zip に track.csv がありません」と出ます。

歩数（steps.csv・meta.json）

GpsLogger の記録には、歩数の記録（steps.csv）が入っていることがあります。このアプリは、GpsLogger の zip から歩数を読み込み、読み込みの知らせに合計の歩数を出し、REPLAY で軌跡と同じ時刻に流します。今は、方位・到達の判定・GS・ETA などの計算には使っていません（画面にも数を出していません）。LIVE で端末の歩数のセンサーは使いません。

  • 読むファイル: zip の中で、名前が session_yyyyMMdd_HHmmss/steps.csv の形（正規表現 ^session_\d{8}_\d{6}/steps\.csv$）に完全一致し、選んだ track.csv と同じフォルダのものだけです。zip の直下・深い所・名前の形が違うもの・別のセッションのものは読みません。同じフォルダの meta.json も読みます。
  • track.csv を 1 つ選んだとき（zip でないとき）は、歩数を読みません（ファイルの選択で読めるのは選んだファイルだけで、同じフォルダの steps.csv を読む権限がないため）。
  • steps.csv がない・見出しだけのときは「歩数なし」で、エラーにしません（知らせにも出しません）。
steps.csv の列意味このアプリでの使い道
typedetector（1 歩ごとに 1 行）か counter（累計歩数の更新ごとに 1 行）行の種類。ほかの値の行は飛ばす
event_elapsed_ns歩のイベントの時刻（端末の起動からの経過時間 [ns]）並べ替えと時刻合わせ（必須。数でない行は飛ばす）
recv_elapsed_nsアプリが受け取った時刻（同じ経過時間）counter の行を区間に振り分ける。REPLAY で「届いた時刻」でも数える（列がなければ event_elapsed_ns）
epoch_msイベントの時刻を端末の時計で直した参考値使わない（時刻合わせにも使わない）
countcounter の累計歩数（detector は空欄）合計の歩数（count のない counter の行は飛ばす）
  • 1 行目は見出しです。列は見出しの名前で探します（順番の違い・知らない列・末尾の欠けに強い）。区切りはカンマ（引用符は使わない）、文字コードは UTF-8、改行は LF・CRLF のどちらも読みます。
  • 行は届いた順に並んでいるので、読んだあと event_elapsed_ns の順に並べ替えます。
  • 時刻合わせ: steps.csv の event_elapsed_ns・recv_elapsed_ns と、track.csv の elapsed_realtime_ns で合わせます（どちらも端末の起動からの経過時間）。epoch_ms どうしでは合わせません（track.csv は GNSS の時刻、steps.csv は端末の時計で、ずれがあるため）。軌跡の点と点の経過時間の間にある歩は、その 2 点の時刻の間に置きます。track.csv に elapsed_realtime_ns のない点があれば、歩数を使いません（知らせに「歩数は使いません（軌跡に経過時間がなく、時刻を合わせられません）」）。
  • 合計の歩数（知らせに出す数）: counter の行があれば、区間（一時停止で区切られた記録の範囲）ごとに「区間の最後の値 − 区間の最初に届いた行（基準値）」を求めて足します。区間の境目は track.csv の gap_before=true の点で、counter の行は recv_elapsed_ns（届いた時刻）で区間に振り分けます（基準値の行の時刻は一時停止より前のことがあるため）。差が負なら 0。基準値の行の時刻は、解析・REPLAY に使いません。counter の行がなければ、detector の行の数です。セッション全体で「最後の値 − 最初の値」を取ると、一時停止中に歩いた分まで入るので、そうしません。
  • meta.json: トップレベルの steps の detector.timebaseAnomalies が 1 以上、または counter.timebaseAnomalies が 2 以上なら、時刻の基準が経過時間でない疑いがあるので、歩数を使いません（知らせに「歩数は使いません（歩数の時刻の基準が合わない記録です）」）。counter の 1 は、前の版の GpsLogger で基準値が数えられていることが多いので使います。meta.json がない・steps がない・JSON として読めないときは、異常なしとして扱います。ほかのキー（status・events など）は使いません。
  • REPLAY: 今の時刻（記録の時計）までの歩数を、歩の時刻で数えた数と、届いた時刻で数えた数の両方で持ちます（シーク・倍速でも、その時刻までの数）。今は、画面にも計算にも使っていません。

3 違う種類のファイルを選んだとき

WP リストと軌跡は、選んだファイルの中身から種類を見分けます。違う種類のファイルなら、読み込まずに知らせます。WP リストのときは、今のリストがそのまま残ります。軌跡のときは、軌跡を読み込んでいないときと同じになります（ほかの理由で読めなかったときと同じく、前の軌跡も外れます）。起動のときに前回のファイルを開くときも同じで、違う種類なら開かずに知らせ、前回のファイルの覚えを消します。

ファイルの中身見分けた種類
CSV で、見出しに epoch_ms か utc_iso8601 がある軌跡（lat・lon があっても）。名前は大文字・小文字を区別して比べる（軌跡の読み込みと同じ）
CSV で、上の列がなく、見出しに lat と lon があるWP リスト。名前は大文字・小文字と前後の空白を問わない（WP リストの読み込みと同じ）
GPX で、<wpt> があるWP リスト（<trk> があっても）
GPX で、<wpt> がなく <trk> がある軌跡（このアプリは GPX の軌跡は再生できません）
zip（GpsLogger で書き出したもの）軌跡
どれでもない決めない（今までどおり、それぞれの読み込みにまかせる）
  • 見るのはファイルの先頭（CSV は最初の空でない行、GPX は先頭の 64 KB）です。CSV の文字コードは、WP リストの読み込みと同じ見分け方です。
  • WP リストとして軌跡のファイルを選ぶと「軌跡のファイルのようです。WP リストとしては読み込めません（ファイルの名前）」、軌跡として WP リストのファイルを選ぶと「WP リストのファイルのようです。軌跡としては読み込めません（ファイルの名前）」と出ます。
