NavHUD ファイル形式

移動目標案内アプリ ・ 20261010-D08 時点 ・ このアプリが読み書きするファイルの説明

1 WP リスト

読み書きできる形式

形式読み込み書き出し入れ方
CSVできるできる起動時の「リストを選ぶ」、または「WP設定」→ インポート / エクスポート
GPXできるできないCSV と同じ（インポート）。読むのは <wpt> だけ
座標の文字できる（1点）—「WP設定」→ 貼り付け（クリップボードの 緯度, 経度）、または 追加・編集の入力欄
  • CSV か GPX かは、ファイルの中身で見分けます。先頭が <?xml か <gpx なら GPX、それ以外は CSV です。ファイルの名前や拡張子は見ません。
  • インポートすると、今のリストと置き換わります（足し込みではありません）。
  • WP リストはアプリの中に保存しません。編集したら、エクスポートで CSV に書き出してください。覚えているのは「最後に読み込んだか書き出したファイルの場所」だけで、次の起動のときにそのファイルを読み直します（設定で、起動のたびに選ぶ形にもできます）。
  • 到達済みかどうかは、ファイルに書き出さず、読み込みもしません。

CSV の決まり

見出し行必要です。1行目（空の行を除いた最初の行）を見出しとして読みます。列は見出しの名前で探すので、順番は自由です。知らない名前の列は無視します。大文字・小文字は区別しません。
区切りカンマ（,）だけです。タブやセミコロンは区切りになりません。
文字コードUTF-8（BOM はあってもなくてもよい）。UTF-8 として読めないときは、Shift_JIS（Windows-31J）として読みます。
改行CRLF・LF・CR のどれでも、混ざっていても読めます。空の行は無視します。
値の囲みカンマ・改行・" を含む値は "..." で囲みます。中の " は "" と書きます。囲んでいない値は、前後の空白を取って読みます。
小数点ピリオド（.）です。カンマは区切りになるので使えません。

CSV の列

列の名前意味必須書かなかったとき書き方の例
lat緯度。10進の度で、−90〜90。南緯はマイナス必須その行は読めない行33.46679346
lon経度。10進の度で、−180〜180。西経はマイナス必須その行は読めない行132.96174603
ele標高 [m]。標高プロファイルに使います省略可標高なし（標高プロファイルに点を描かない）1300
name名前。画面の文字と WP ボタンに出ます省略可WP1・WP2…（読めた順の番号）展望台
target_time目標時刻（端末の時刻）。TGT の計算に使います省略可目標時刻なし（TGT は ---）08:30 8:30 8:30:00
deadline_time締切時刻（端末の時刻）。DDL の計算に使います省略可締切時刻なし（DDL は ---）08:45
enabled有効か無効か。無効の WP は目標にせず、グレーの破線で描きます省略可有効1（有効）0（無効）。true / false も可
radiusこの WP だけの到達半径 [m]。0 より大きい数。この半径に入ったら到達にします省略可全体の設定（到着半径。初期値 30 m）を使う100
  • enabled と radius は、このアプリ独自の列です。ほかの 6 列だけの CSV も、そのまま読めます。
  • 時刻は 時:分 か 時:分:秒 です（時は 0〜23、1桁でもよい）。日付は持ちません。全角の数字・コロンで書いても読めます。0830 や 8時30分 は読めません。
  • radius がある WP では、通過の予備判定の「近づいた距離の上限」も、半径 × 3 の方が大きければそちらを使います。

緯度・経度の書き方

場所読める書き方読めない書き方
CSV の lat・lon の列10進の度を、列を分けて書く。33.46679346、-33.4、+33.4。前後の空白は可度分秒（33°28'00"）、N33.4 のような文字つき、範囲の外の数
貼り付け、追加・編集の入力欄緯度, 経度 を1行で。34.69370, 135.50230（Google マップでコピーした座標の形）。カンマの前後の空白はあってもなくてもよい。符号も可かっこつき、空白だけで区切ったもの、URL、度分秒、2行以上
GPX の <wpt>lat・lon の属性に、10進の度範囲の外の数、数でない値

読めない行があったとき

  • その行だけを飛ばし、読めた行でリストを作ります。読み込みは止まりません。
  • 読み込みのあと、「WP設定」の画面に「○○ から N 件を読み込みました（読めない行 M 件をスキップ）」と出ます。
  • 読めない行になるのは、次のどれかのときです。
    • lat・lon が空、数でない、範囲の外。
    • ele が数でない（空はよい）。
    • target_time・deadline_time の形が違う（空はよい）。
    • enabled が 1・0・true・false・空 のどれでもない。
    • radius が 0 以下、または数でない（空はよい）。
  • 見出し行に lat と lon がないと、すべての行が読めない行になります（見出しのない CSV も同じです）。

サンプル（CSV）

このまま waypoints.csv として保存すれば読み込めます。

lat,lon,ele,name,target_time,deadline_time,enabled,radius
33.47649101,133.00275172,1300,峠の入口,,,1,
33.46679346,132.96174603,,展望台,08:30,08:45,1,
33.48377796,132.87220649,,旧道（通行止め）,,,0,
33.48750794,132.90060923,,道の駅,09:10,09:20,1,100
33.55944388,133.00766313,,ダム,,,1,
33.667743,132.8949383,,終点,11:00,,1,

3行目は無効の WP（enabled が 0）、4行目は到達半径 100 m の WP です。空の欄は「なし」になります。

書き出し（エクスポート）

  • CSV だけです。列は上の 8 列を、この順番で書きます。はじめのファイル名は waypoints.csv です。
  • 文字コードは UTF-8（BOM つき）、改行は CRLF です。Excel でそのまま開けます。
  • 緯度・経度は桁を落とさずに書きます。時刻は 08:30（秒があれば 08:30:15）、enabled は 1 か 0 です。値のない欄は空にします。
  • カンマ・改行・" を含む名前や、前後に空白のある名前は、"..." で囲んで書きます。
  • 書き出した CSV は、そのまま読み込めます（上のサンプルは、書き出したときの形と同じです）。

GPX

読むのは、ファイルの中の <wpt>（ウェイポイント）だけです。<rtept>（ルートの点）と <trkpt>（軌跡の点）は読みません。

GPX の中身WP の項目書かなかったとき・読めないとき
wpt の lat・lon緯度・経度（必須）その <wpt> を飛ばして、件数に数える
<name>名前WP1・WP2…
<ele>標高 [m]標高なし
<time>目標時刻目標時刻なし
<extensions> の <deadline>締切時刻締切時刻なし
  • <time> と <deadline> は、日付つきの時刻（2026-08-13T23:30:00Z の形）なら、端末の時刻帯の時刻に直して使います（日本なら 08:30）。08:45 のように時刻だけを書いてもかまいません。
  • 有効 / 無効と、WP ごとの到達半径は GPX では指定できません。すべて「有効」「全体の設定の半径」になります。
  • XML として読めないファイルは、0 件になります。
<?xml version="1.0" encoding="UTF-8"?>
<gpx version="1.1" creator="example" xmlns="http://www.topografix.com/GPX/1/1">
  <wpt lat="33.46679346" lon="132.96174603">
    <ele>1280</ele>
    <time>2026-08-13T23:30:00Z</time>
    <name>展望台</name>
    <extensions><deadline>08:45</deadline></extensions>
  </wpt>
  <wpt lat="33.48750794" lon="132.90060923">
    <name>道の駅</name>
  </wpt>
</gpx>

2 軌跡（再生用の記録）

REPLAY で再生する記録です。上部の ⇄ で REPLAY にして、FILE で選びます。読めるのは、GpsLogger が記録する track.csv と、GpsLogger で書き出した zip です。書き出しはありません。

GpsLogger の形式そのものの説明は、GpsLogger の説明を見てください: https://github.com/eightbrows/GpsLogger

track.csv でこのアプリが使う列

列の名前意味このアプリでの使い道
latitude緯度 [度]位置（必須）
longitude経度 [度]位置（必須）
epoch_ms時刻（1970 年からのミリ秒）時刻（必須。再生の進み方、TIME、TGT・DDL・ETA の計算）
utc_iso8601時刻（2026-08-13T22:52:35.000Z の形）epoch_ms が読めない行で、代わりに使う
altitude_ellipsoid_m高さ（楕円体高）[m]ALT（ここから標高オフセットを引く）、RATE の高度差、標高プロファイルの現在地
speed_mps速度 [m/s]GS、RATE の移動距離、ETA、方位の保持、真横通過の判定
bearing_deg進行方位 [度]HDG（GPS の方位）、真横通過の判定
bearing_acc_deg方位の精度 [度]GPS の方位を使うかどうか。0 か空の行は「方位なし」（停止中）として扱う
horizontal_acc_m位置の精度 [m]GPS の方位を使うかどうか（設定の上限と比べる）
  • これ以外の列（provider・gdop など）は読みません。GpsLogger のほかのファイル（sats.csv・meta.json・track.gpx・track.kmz）も読みません。
  • 1行目は見出しです。列は見出しの名前で探すので、順番が違っても、列が増えていても読めます（名前の大文字・小文字は区別します）。区切りはカンマ、文字コードは UTF-8 です。
  • 緯度・経度・時刻のどれかが読めない行は飛ばします。読める行が1つもないと、「○○ に読める行がありません」と出ます。
  • bearing_acc_deg の列がない記録では、速度が 0 の行を「方位なし」として扱います。
  • 記録の途中の抜け（時刻の間があいた所）は、そのまま再生します。抜けが長いと NO FIX になります。

zip から読むとき

  • GpsLogger で書き出した zip を、そのまま FILE で選べます。zip かどうかは、名前ではなくファイルの中身で見分けます。
  • zip の中の session_yyyyMMdd_HHmmss/track.csv を探します。名前が track.csv のファイルなら、フォルダの深さは問いません。ほかのファイルは読み飛ばします。
  • zip を開くと、中のセッションの一覧が出ます。セッションが1つだけでも一覧を出します。1つ選ぶと、その記録を再生します。セッションをつないで1本にはしません。
  • 一覧は、開始時刻の新しい順です。1行に、開始時刻（端末の時刻帯）、長さ、点の数、フォルダの名前が出ます。読める行のないセッションは、一覧には出ますが選べません。
  • 選んだ zip とセッションを覚えていて、次の起動では同じセッションを開きます。そのセッションが zip の中に見つからないときは、一覧を出します。
  • zip の中身は、端末に展開しません。必要な track.csv だけを読みます。
  • 壊れた zip や途中で切れた zip は「zip として読めませんでした」、track.csv の入っていない zip は「zip に track.csv がありません」と出ます。
