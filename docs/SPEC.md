# NavHUD 仕様書

## 1. 概要
- アプリ名: ナビHUDアプリ / NavHUD
- 用途: 地上（自動車・徒歩など）でのナビゲーション表示。航空機の ND/HSI 風の黒背景・線画。
- ウェイポイント(WP)の座標リストに対して、自機位置・方位・距離・到着予定などを表示する。
- 地図は持たない（背景画像は §8 の低優先機能）。記録はしない。フォアグラウンドでのみ動作。

## 2. サンプルデータ（track.csv）
自作GPSロガーの生データ。リプレイ用インポート形式であり、開発・テストのサンプル。

### 2.0 置き場所と git の扱い
- track.csv は**意図的に git 管理外**。`/sample` は `.gitignore` で除外したままにする。
- 開発機では `sample/session_20260814_075234/track.csv` に置く。
- track.csv を使う単体テストは、ファイルがなければ JUnit の `Assume` でスキップする（失敗にしない）。
- 実機でのリプレイは、端末の Download フォルダに置いた track.csv を選んで使う（§6.7）。

## 3. データ型（core/model）

### 3.1 Fix（位置1件。実機GPSとリプレイで共通）
| フィールド | 型 | 説明 |
|---|---|---|
| timeMs | Long | UTC epoch ms |
| lat, lon | Double | 度 |
| altRawM | Double? | 楕円体高（生値）。表示時に標高オフセットを引く |
| speedMps | Float? | 対地速度 |
| bearingDeg | Float? | 進行方位（真北, 0..360）。**null = 方位なし** |
| horizAccM | Float? | 水平精度 |

### 3.2 Waypoint
| フィールド | 型 | 説明 |
|---|---|---|
| name | String | |
| lat, lon | Double | |
| eleM | Double? | 標高 |
| targetTime | LocalTime? | 目標時刻（ローカル） |
| deadlineTime | LocalTime? | 締切時刻（ローカル） |
| enabled | Boolean | 既定 true |
| reached | Boolean | 既定 false |

### 3.3 enum
- `SourceMode { HYBRID, GPS, COMPASS }` — ユーザーが選ぶ方位ソース
- `HeadingSrc { GPS, COMPASS, NONE }` — 実際に使われている方位ソース

### 3.4 ソースのインターフェース
```kotlin
interface PositionSource { val fixes: Flow<Fix> }        // Live GPS / Replay
interface HeadingSource  { val headingDeg: Flow<Float> } // コンパス（真北補正済み）
```

## 4. トラックCSVの読み込み（core/io）
- 1行目ヘッダ。UTF-8 BOM があれば除去。列はヘッダ名で引く（順序・追加列・末尾列欠けに強く）。
- 必須: `latitude`, `longitude`, 時刻（`epoch_ms` 優先、なければ `utc_iso8601` を ISO8601 解析）。
- 任意: `altitude_ellipsoid_m`→altRawM, `speed_mps`, `bearing_deg`, `bearing_acc_deg`, `horizontal_acc_m`。空欄は null。
- **方位の有効判定**: `bearing_acc_deg` 列がある場合は `bearing_acc_deg > 0` のときだけ有効。列がない場合は speed が null または > 0 なら有効。無効なら bearingDeg = null。
- 必須項目が読めない行はスキップし、スキップ数を返す（例外にしない）。
- 戻り値: `(fixes: List<Fix>, skippedLines: Int)`

## 5. 計算コア（core/geo, core/nav）

### 5.1 地理計算
- 距離: 大圏距離（haversine, 地球半径 6,371,000m）
- 方位: 初期方位（真北基準 0..360）
- 角度差: from→to の最短回転 (-180, 180]
- 平面近似: 自機を原点とする正距円筒（東m, 北m）。数十km以内で使う。
- 画面座標: 上方向を `upDeg` とする回転（Heading Up は upDeg = 機首方位、North Up は 0）。
  `right = e·cos(h) − n·sin(h)`, `fwd = e·sin(h) + n·cos(h)`

### 5.2 方位選択（HeadingSelector）
- 方位ソースの既定は **GPS**（実機テストで、車内ではコンパスが不安定だったため）。HYBRID と COMPASS は歩行用に残す。
- GPS 方位が「使える」条件: bearingDeg ≠ null かつ（水平精度が null または ≤ 15 m）かつ（方位の精度が null または ≤ 20°。値を出している端末のみ）。
- **GPS 方位の保持（ヒステリシス）**: 速度が「保持開始速度」（既定 2.0 m/s ≒ 7km/h）未満で保持に入り、「保持解除速度」（既定 3.0 m/s ≒ 11km/h）を超え、かつ GPS 方位が使えるときに GPS 方位に戻る。
  - 保持する値は、保持解除速度以上で走っていた間の最後の方位（減速中のふらついた値は使わない）。
  - 保持中は数値の表示の HDG の付記を **HLD** にする。HLD は速度による保持だけを表す。走行中に方位の精度が悪い Fix が混ざったときは、HLD にせず直前の使えた GPS 方位のまま。
  - 状態は Fix が来たときだけ更新する（tick やコンパスの値では変えない）。
- GPS モード: 今の GPS 方位。保持中は保持した方位（HLD）。どちらもなければ NONE。
- COMPASS モード: コンパス値（なければ NONE）。
- HYBRID: 今の GPS 方位 → （保持中は）コンパスが CAL でなければコンパス → 保持した GPS 方位 → CAL のコンパス → NONE。
- 値はすべて NavSettings に置く（設定画面 §6.9 で変えられる）。
- 切替時のスムージングはオプション（後回し可）。

### 5.3 RATE（移動距離・高度差・平均速度）
- 窓: 10 / 30 / 60 秒（上部の RATE 行で切替）。平均速度は ETA にも使う（§5.4）。
- 直近の Fix を保持（最大窓 + 余裕分）。窓の起点 = 最新時刻 − 窓秒。起点以前で最も新しい Fix を base とする。
- base がない、または base が起点より 2 秒を超えて古い（= 欠損）→ **null（表示 "---"）**。
- 距離 = base→最新の各区間の和。区間は両端の速度があれば **速度の台形積分**（停止中のジッタを拾わない）、速度がない区間と **間隔 > 2秒の欠損区間は直線距離**。
- 高度差 = 最新 altRawM − base altRawM。平均速度 = 距離 / (最新時刻 − base 時刻)。

### 5.4 ウェイポイント
- 次の目標 = enabled かつ未 reached のうち番号（リスト順）最小。なければ null。
- **到達の判定**（次の WP に対して、上から順に見る。どれかを満たしたら reached = true → 自動的に次へ）:
  1. **WP ごとの半径**（§7.1 の radius）がある WP: その半径に入ったら到達（到着半径の代わり）。
  2. **到着半径**（全体の到達半径。既定 30 m、30/50/100/200/500m から選ぶ。停車・目的地そのものへ行く場合）: 入ったら到達。
  3. **真横通過**（既定オン）: 次をすべて満たしたら到達。道路脇の目標物でも、真横に来た時点を通過にする。
     - 速度 ≥ 方位を使う速度（HLD を解く速度、既定 3.0 m/s）で、GPS 方位がある（方位の精度が分かれば上限以内。HLD 中は使わない）。
     - WP までの距離 ≤ 真横通過の距離（既定 150 m）。
     - WP への方位と進行方位の差 ≥ 90°（WP が真横か後ろ）。
     - いちばん近づいた距離から +10 m（既定）以上離れた。いちばん近づいた距離は、隣り合う Fix を結んだ線分と WP の最短距離。
  4. **通過判定**（予備。既定オン。方位が取れない場面用）: 最接近距離 ≤ 300 m のあと、距離が「最接近距離 + 50 m」以上の状態が 5 秒続いたら到達。
     - 最接近距離は線分と WP の最短距離（記録の欠損中に通過しても拾える）。WP ごとの半径があれば、最接近距離の上限は max(300 m, 半径 × 3)。
- 3・4 の記録（いちばん近づいた距離）は、次の WP が変わったら（到達・手動トグル・並べ替えなど）リセットする。
- **移動手段**（設定 §6.9）: 自動車（既定）/ カスタム1 / カスタム2 / カスタム3。対象は到達判定の値（到着半径、真横通過のオン/オフ・距離・離れる距離、通過判定のオン/オフ・距離・離れる距離・秒数）だけで、AUTO 縮尺などほかの設定は対象外。
  - 自動車: 推奨値（到着半径 30 m、真横通過 オン・150 m・+10 m、通過判定 オン・300 m・+50 m・5 秒。Tuning.CAR_*）で固定。設定画面では値を表示するだけで変えられない（グレー）。
  - カスタム1〜3: 枠ごとに値を保存し、次の起動でも覚えている。ほかの枠や自動車に切り替えても消えない。枠ごとに「自動車の値に戻す」ボタンがある。最初は自動車の値。
  - 値が推奨値と同じかどうかで移動手段を自動で決めることはしない。自転車・徒歩はあとで足す。
- 前の版で保存した設定の移行: D06・D07 の「カスタム」と、D06 より前の設定（移動手段の項目がない）は、保存してあった到達判定の値（到達半径 100 m など）をカスタム1 に移し、カスタム1 を選ぶ。カスタム2・3 は自動車の値で始める。「自動車」の端末は自動車のまま。保存がない（新しく入れた）端末は自動車。
- **到達の理由**（WP 一覧に出す。§6.5）: 到達した WP ごとに、理由・到達した Fix の時刻（REPLAY ではログの時刻）・その WP にいちばん近づいた距離を記録する。
  - 理由: 半径（WP ごとの半径）/ 到着（到着半径）/ 真横（真横通過）/ 通過（通過判定・予備）/ 手動（WP ボタン）。前方へのシークで飛ばした区間の判定なら「シーク・真横」のように前に「シーク」を付ける。
  - いちばん近づいた距離は、隣り合う Fix を結んだ線分と WP の最短距離（次の WP になってからの分）。手動では時刻だけ（そのときの時刻）。
  - 未到達に戻したら（手動トグル、先頭へのシーク、逆順）消す。到達の状態は保存しない（§7.1）ので、理由も保存しない。
- つづら折りや並行道路で、道が WP の近くを2回通る所では、1回目の接近で 2〜4 が到達にすることがある。誤判定は手動トグルで戻せる。
  - 2回通る所の対策として、真横通過に条件を足す案を試したが、採用していない（D07）。案 A は「最接近のとき WP が真横（60〜120°）だった」、案 C は「距離の上限に入ってから進行方位が 100° 以上変わったら真横通過を使わない」。
  - track.csv の2回通る5か所では、どちらの案でも結果が変わらなかった。原因の内訳は、到着半径（1回目も 30 m 以内）が2か所、予備の通過判定が1か所、なめらかなカーブでの真横通過が1か所で、残る1か所は早すぎなかった。
  - 合成のヘアピンでは、どちらの案も真横通過を止めたが、予備の通過判定が到達にした。
- 手動トグル: 指定 WP の reached を反転。**個別で他の WP に連動しない**。無効 WP は操作不可。
- ETA = 現在時刻 + 直線距離 / 平均速度（§5.3 の RATE の窓）。平均速度 < 0.5 m/s なら null。
  - 履歴が窓に足りない（走り始め・欠損のあと）ときは、窓の中にある分の平均速度を使う。ある分が 10 秒未満なら null。
- 目標/締切カウントダウン: 対象時刻 − 現在時刻（ローカル時刻、秒）。過ぎたら負。日付を持たないため差が ±12時間を超えたら 24時間で折り返す。

### 5.5 NO FIX
- 最後の Fix から設定秒数（既定 10 秒）を超えたら NO FIX。一度も測位していなければ NO FIX（起動直後の未測位・途切れた後・リプレイの欠損、どれも同じ NO FIX）。
- ログの欠損検出（テスト・デバッグ用）: 隣接 Fix の間隔 > 1.5 秒を欠損とする。

## 6. 画面・動作

### 6.1 メイン画面（共通）
- 黒背景、線画。自機マーカー、ラバーライン、上部の三角マーカー。
- **画面の構成**: 地図の Canvas を、ステータスバーの下から画面の下端（ナビゲーションバーの下）まで、左右いっぱいに描く。ほかの表示はすべて地図の上に **重ねる**。
  - 上から: **上部バー**（HDG / WP / ⇄ INPUT / FILE / ARC / ⚙）/ **数値**（4行、下記）/ **地図** / **横並びの WP ボタン列**（40dp、§6.4。上部バーの WP で表示 / 非表示）/ **標高プロファイル**（§6.6）/ REPLAY のときだけ **再生の帯**（36dp、§6.7。画面の一番下・ナビゲーションバーの上）。地図の右端に **操作列**（幅 60dp。上から − / RNG / ＋ だけ。回避枠の縦中央に置く。PAN 中の「現在地」は ＋ のすぐ下）。寸法は Tuning.kt。
  - 重ね方: ボタン類（上部バー・操作列・WP ボタン列・再生の帯）は **背景を塗らない**（枠と文字だけ。下の地図の線が見える）。枠は色と太さで押せることが分かるようにし、文字には数値と同じ黒の縁取りを付ける。状態を色の反転で見せるボタン（到達済みの WP、AUTO、WP など）は反転の塗りを残す。標高プロファイルは半透明の黒の地（不透明度 Tuning.OVERLAY_ALPHA）。数値の表示は背景の箱なしで、文字に黒の縁取り（太さ Tuning.TEXT_OUTLINE_DP）を付けて線や環の上でも読めるようにする。
  - 不透明度（設定 §6.9）: **ボタンの不透明度**（既定 70%、20〜100%、10% 刻み）を、地図に重ねるボタン（上部バー・操作列・WP ボタン列・再生の帯。枠・文字・記号・縁取り、押せないグレーのボタンも。再生の帯の ×N・時刻・スライダーも同じ）にかける。ON（反転）の塗りの不透明度は ボタンの不透明度 × Tuning.BUTTON_ON_FILL_ALPHA（既定 0.5）で、裏の地図の線が透けて見える。ON の文字は黒に、ボタンの色の細い縁取り（Tuning.BUTTON_ON_TEXT_OUTLINE_DP）。**数値の不透明度**（既定 100%、20〜100%、10% 刻み。お試し）を、数値4行の見出し・値・縁取り（NEXT のマゼンタも含む）にかける。警告の表示（NO FIX の枠、締切を過ぎた DDL、CAL / MAG の付いた HDG）は常に 100%。設定画面・WP 設定画面・案内の枠のボタンは変えない。既定値は Tuning.kt。
  - 操作: ボタンの上ではボタンが優先。それ以外（上部バーの空き部分などを含む）のドラッグは地図に渡す（PAN）。
  - **描画の枠** = 地図の Canvas 全体。距離環・方位線・トラック・軌跡・WP の線と印はこの枠に描き、重ねた表示の下にもかかる。
  - **回避枠** = 描画の枠から、重ねた表示を除いた真ん中の部分。上は数値の下端、下は WP ボタン列の上端（WP ボタン列を隠しているときは、その下の表示の上端）、右は操作列（＋ / RNG / −）がある高さの範囲だけ操作列の左端。North Up と PAN の中心の高さ（縦中央）、ARC の自機の高さ、方位目盛りの上端、操作列の高さ、NO FIX などの案内の枠に使う。North Up と PAN の中心の横位置は **描画の枠（画面）の左右中央**。
  - **画面外の矢印と AUTO 縮尺の判定の枠** = 上は数値の下端。右は、操作列がある高さの範囲だけ操作列の左端、それより上・下は描画の枠の右端。左・下は描画の枠の左端・下端（下に重ねた表示の下も地図として見えている扱い）。**矢印を置く枠** は、この枠の下端だけを WP ボタン列の上端（下に重ねた表示の上端）にしたもので、矢印はその縁から 22dp 内側に置く（矢印と文字を WP ボタン列・標高プロファイル・再生の帯の下に置かない。AUTO の判定の枠は変えない）。矢印が自機の記号にかかるとき（真後ろなど）は、縁に沿って横へずらす。
  - **画面外の矢印を出す条件**: 次の WP が、重ねた表示の下（矢印と AUTO の判定の枠の外。上部バー・数値の下、操作列の下）か描画の枠の外にあるときだけ。見えている所（その枠の中。下に重ねた表示の下も含む）なら印だけで矢印は出さない。印は描画の枠の中ならどこでも描く。
  - **WP の名前を出さない所**: WP の名前が、数値の表示（上下の範囲。左右は画面いっぱい）か、ボタン類（上部バー・操作列・WP ボタン列・再生の帯）に重なるときは名前を出さない。印と線は描く。標高プロファイルは対象外。 WP の名前どうしが重なるときは、次の WP の名前だけ出す（ほかはルートの順に先に置いた名前を残す。もう一方は印と線だけ）。
- 上部バー: **HDG**（方位ソースの選択 HYBRID / GPS / COMPASS）、WP ボタン（WP ボタン列の表示/非表示）、**INPUT**（`⇄ LIVE` / `⇄ REPLAY`。タップで LIVE / REPLAY の切替）、**FILE**（track.csv を選ぶ。REPLAY のときだけ）、表示モード（ARC / North Up）、**⚙**（設定画面 §6.9。長押しで開発用画面）。幅が足りないときは、文字を短くする前に案を出して決める。
- 数値の表示（上部バーの下、4行。見出しは値の左に小さく）: 1行目 TIME（ローカル）・ALT（楕円体高 − 標高オフセット）・RATE（10/30/60s 切替。移動距離と高度差。タップで窓を切替）、2行目 HDG・GS・ETA、3行目 NEXT・TGT・DDL、4行目 LAT/LON。
  - HDG は値の横に実際に使っている方位ソースを小さく付記（`053° GPS` / `053° CMP`。コンパスの印 CAL / MAG もここに黄色で）。NEXT は WP の名前・方位・距離（名前は入りきらなければ … で省略。方位と距離は必ず出す）。TGT は目標時刻カウントダウン、DDL は締切カウントダウン（超過で色変更）。
- WP: 登録順に線で結ぶ。無効 WP はグレー破線。画面外の矢印（矢印の枠の縁に方位方向の三角＋距離）は、次の WP（マゼンタ）の分だけ出す。ほかの WP の矢印は出さず、次の WP が画面内なら矢印はない（ARC・North Up・PAN とも）。
  - 描く WP は、次の WP から先の目標（有効かつ未到達）N 個（設定、既定 15、1〜20）と、直前に到達した WP 1つ（暗め）。目標の間にある無効 WP は数えずにグレーで描く。線もこの範囲だけ。
- 距離環: 間隔は縮尺の段の 1/2。縮尺（ARC の基準の環・North Up の最外周）より外側も、同じ間隔で描画の枠の四隅に届くまで描く（例: 1 km なら 500 m, 1k, 1.5k, 2k, …）。文字はすべての環に付ける。文字は、1000m 未満は m の数字だけ（`25` / `50` / `100` / `250` / `500`）、1000m 以上は k（`1k` / `2.5k` / `5k` / `10k` / `25k`）。方位目盛りの文字より小さく薄い色。方位目盛りの文字と重なる距離環の文字は出さない。
- 文字の重なり: 画面外の矢印の文字は、方位目盛り・距離環の文字、自機の記号、上部の方位マーカー、画面内の WP の印と名前、その矢印自身、先に置いた矢印の文字と重ならない位置に置く（自機側・線と直角の両側へ1行ずつずらして探す。最大3行）。WP の名前は印の上、自機の記号と重なるなら下、それでも重なるなら描かない。到達済みの WP は下へ逃がさず、自機の記号と重なるなら名前を描かない（PAN 中も同じ）。
- 画面外の矢印（三角）が方位目盛り・距離環の文字に重なるときは、矢印の枠の縁に沿ってずらす（三角の大きさずつ両側へ、最大4段）。 ARC の上部中央の方位マーカー（三角）とラバーラインの周り（マーカーの左右 2 つ分の幅）に来るときも、横にずらす。
- NO FIX 時: 回避枠の中央にメッセージ枠。最後の値はグレーで表示し続ける。
- **当面の扱い（§10 の未決定事項）**: 画面の向きは縦固定。
- **縮尺（ARC / North Up 共通）**: 段階的な縮尺 **50m / 100m / 200m / 500m / 1km / 2km / 5km / 10km / 20km / 50km**（ARC では基準の距離環が画面の左右端に接する距離、North Up では最外周の距離環）。使う段は設定で選ぶ（既定 100m〜20km）。起動時は 1km。
  - 操作列の上から **− / 縮尺の表示 / ＋**（52dp 角。− = 広く、＋ = 狭く）。縮尺の表示は2行（`AUTO` / `RNG` / `PAN` と、距離）で、タップすると AUTO の ON / OFF。**縮尺の表示は1つ目の距離環の距離**（自機から1つ目の距離環 = 縮尺の段の 1/2。1km の段 → `500m`、2km → `1km`、5km → `2.5km`）。表記は `25m` / `50m` / `100m` / `250m` / `500m` / `1km` / `2.5km` / `5km` / `10km` / `25km`。設定画面の縮尺の項目（使う段、起動時の縮尺）も同じ表記。内部の段の値（50m〜50km）は変えない。
  - **AUTO**（既定 ON）: 次の WP を収める距離で決める。ただし上限・下限を持ち、近い WP どうしを区別できる縮尺より広げない。縮尺は「1つ目の距離環の距離（R1）」で考える。判定（Fix・時計の刻みごと）では、次のうち上から1つだけ行い、1回に動かすのは1段だけ。
    1. **次の WP がない**（全部到達・リストなし）: 下限〜上限の使う段の中央の段（2つあれば広い方）へすぐ動かす。
    2. **今の段が [AUTO の下限, AUTO の上限] の外**（AUTO を ON にした直後、設定を変えたときなど）: すぐ範囲の端の段へ。
    3. **WP を区別できる幅**: 描画の枠の中に見えている、ルート上で隣り合う2つの目標（次の WP から先の有効・未到達の WP。HUD に描く数まで。無効は飛ばす。到達済みと自機は数えない）の画面上の距離が、Tuning.AUTO_WP_MIN_SEP_DP（既定 40dp）より短く、かつ1段狭い段でも次の WP が枠に収まるとき、すぐ1段狭める（下限より狭めない）。1段狭めると次の WP が枠に収まらない（見えなくなる）なら、近すぎても狭めない。規則 4・5 より優先。
    4. **広げる**: 次の WP が今の段で矢印と AUTO の判定の枠（上は数値の下端、右は操作列の高さの範囲だけ操作列の左端、ほかは描画の枠。縁から 22dp、さらに余白 16dp の内側）の外に出たら、すぐ1段広げる。ただし上限まで、かつ広げた段で 3 を満たすとき（区別できる、または1段狭い段では次の WP が収まらない）だけ。広げられなければ今の段のままで、矢印で示す。
    5. **狭める**: 次の両方を満たす状態が「AUTO で狭めるまでの時間」（既定 5 秒）続いたら、1段狭める。待ちはトラックの時刻で数える（REPLAY の一時停止中は進まない）。
       a. 次の WP までの距離 ≤ **AUTO で狭め始める距離**（設定。既定 2.0、1.0〜4.0、0.5 刻み）× 1段狭い段の R1。例: 500m の段（R1 250m）→ 200m の段（R1 100m）は、WP まで 200m 以内。
       b. 1段狭い段で、次の WP を自機から見て 1 / Tuning.AUTO_ZOOM_IN_FIT_RATIO（既定 0.8 → 1.25 倍）遠くに置いても枠に収まり、3 も満たす。
    - **WP 通過後の待機**: 次の WP が変わった時刻（自動の到達・通過判定、手動のトグルとも）から「WP 通過後に AUTO が動くまで」（設定。既定 10 秒、0〜60 秒）のあいだは、1〜5 のどれも行わない（段を動かさない。矢印は通常どおり出す）。待ちはトラックの時刻で数える。シーク・PAN から戻ったときは待たない。
    - PAN から現在地へ戻ったとき・シークのあとは、1段ずつではなく、待たずに目標の段（下限〜上限で次の WP が収まるいちばん狭い段。3 を満たさなければ満たす段まで狭める）にする。
    - ＋ / − を押したら AUTO は OFF（手動では下限・上限の外の段にもできる）。PAN 中（§6.10）は止める。ARC / North Up で同じ規則（ARC は機首方位と自機の位置を、North Up は縮尺の距離環の半径を反映）。
    - **AUTO の下限・上限**（設定 §6.9）: 既定は下限 R1 50m（100m の段）、上限 R1 500m（1km の段）。使う段から R1 の表記で選ぶ（下限 ≤ 上限）。使う段から外れたら、下限は元の値以上でいちばん狭い段、上限は元の値以下でいちばん広い段に寄せる（なければ使う段の端）。
  - 画面の大きさがまだ分からないときは、距離で判定する（次の WP が「縮尺 × 0.9」以内なら収まる。3 は判定しない）。対地速度も受け取るが、今は使わない（将来「速度に応じた縮尺」のため）。
- 色は航空機の ND の慣習に合わせる: 背景は黒、薄い方位線は暗いグレー。次の WP とそこへの線はマゼンタ、無効 WP はグレーの破線、到達済み WP は暗めの色。警告（NO FIX、締切超過）は黄〜赤。NO FIX 中の値はグレー。
  - **色**（設定）: 基本色を次の2つに分けて、それぞれ **白 / 緑 / 琥珀** から選ぶ。マゼンタ（次の WP）・黄 / 赤（警告）・グレー（無効 WP・NO FIX）はどちらの設定にも左右されない。色の定義は ui/HudColors の1か所（UI 用と地図用の2組）。
    - **UI の色**（既定 白）: 上部バー・数値・右の操作列・WP ボタン列・標高プロファイル・再生の帯（ボタンの枠と文字、数値）。
    - **地図の色**（既定 緑）: 地図の Canvas に描くもの（距離環と文字、方位線、方位目盛り、自機、ラバーライン、方位マーカー、WP の印と名前、画面外の矢印、トラック・軌跡）。
    - 古い版の「色テーマ」（1つ）が保存されていれば、UI・地図の両方の初期値として引き継ぐ。

### 6.2 ARC モード（Heading Up）
- 自機は **画面の横中央**。高さは回避枠の下端（WP ボタン列の上端）から、設定で **標準（24dp。WP ボタン列のすぐ上）/ 高め（84dp。そこから 60dp 上）**（値は Tuning.kt）。LIVE・REPLAY とも WP ボタン列の上端が基準で、再生の帯の分の補正はしない（再生の帯は WP ボタン列より下にあるため、帯があると WP ボタン列ごと 36dp 上がる）。
- 距離環は全周（後ろ側も前と同じ線・同じ文字の処理）を描画の枠の四隅まで描く。30° ごとの方位線と方位目盛りは前方 180° だけ。
- 縮尺: 基準距離環（縮尺の段）が画面の左右端にちょうど接するように拡大。
- 方位目盛りは同心円に沿わせない。自機から各方位へ引いた線と、**上は回避枠の上端（数値の下端）、左右は描画の枠（画面）の左右端** の枠との交点に置く（右の操作列の下に入ってもよい）。上部中央の方位マーカー（三角）は自機の真上、回避枠の上端に置く。
- 30°ごとに薄い方位線を引く。ラバーライン（自機の前方向の線）は描画の枠の上端まで伸ばす（上部の三角マーカーの位置は回避枠の上端のまま）。

### 6.3 North Up モード
- 全周コンパスカード（HSI 風）。自機は、横は描画の枠（画面）の左右中央、縦は回避枠の縦中央。**縮尺の距離環**（AUTO の判定に使う環）の半径は **min(画面の幅の半分, 回避枠の高さの半分) − 8dp**（Tuning.HUD_NORTH_UP_EDGE_MARGIN_DP）。**方位サークル**（目盛り・方位の文字が付いた円）は、縮尺の距離環の **1つ外側の距離環**（例: 縮尺 5km なら 7.5km の環）に描く。画面からはみ出してよく、はみ出した目盛りと文字は切れてよい。右の操作列と重なってよい。目盛りと方位の文字はサークルの **内側** に、円から内側へ 長い目盛り・短い目盛り・文字の順に描く。方位の文字が数値の表示・ボタン類（上部バー・操作列・WP ボタン列・再生の帯）に重なるときは出さない（目盛りの線は描く）。向いている方向の線（ラバーライン）は描画の枠の端まで伸ばし、機首方位の三角は縮尺の距離環の上に置く。内側の距離環と、描画の枠の四隅まで描き足す外側の距離環は ARC と同じ（間隔は縮尺の 1/2）。

### 6.4 WP ボタン列（地図の下の方に重ねる、横並び）
- 自機の下のスペース（標高プロファイル・再生の帯の上、高さ 40dp）に横並び。左端に固定の「WP設定」ボタン（幅 64dp）、その右は左から WP1, WP2, WP3…（左右にスクロール）。
- 一度に見せるボタンの数を設定で選ぶ（既定 4、3〜6）。ボタンの幅はこの数で決まる。次の WP が変わったら、それが「WP設定」を除いて左から2番目に来るよう自動でスクロールする（1番目は1つ前の WP）。次の WP がリストの最初なら1番目（左詰め）。リストの最後のほうでも2番目のままで、右側は空いてよい。
- **タップ**: 到達済みを個別にトグル（色反転で表示）。無効 WP はグレーで押せない。
- **長押し**: その WP を地図の中心にした PAN にする（§6.10）。無効 WP も長押しは効く。

### 6.5 WP設定画面
- ≡ のドラッグで並べ替え、有効/無効スイッチ、編集（名前、"lat, lon" の1フィールド、標高、目標時刻、締切時刻）、追加、貼り付け、インポート、エクスポート。
- WP 一覧の到達済みの WP は、行の下に到達の理由を 1 行出す（§5.4）。例: 「真横 08:12:34 最接近 42 m」「シーク・真横 …」「手動 08:12:34」。メイン画面の WP ボタン列には出さない。
- 貼り付け: Google マップでピンを立ててコピーした座標 `34.69370, 135.50230` 形式。
- 編集の項目に **到達半径**（m、空欄で全体の設定）。
- **逆順にする**: リストの順番を反転し、到達済みをすべて解除する（確認のダイアログを出す）。
- **時刻を一括調整**: 基準の WP（目標時刻の入った WP から選ぶ。既定は先頭の、有効で目標時刻の入った WP）と、その新しい目標時刻を入力する。目標時刻の入った WP（無効 WP も含む）を並び順に取り出し、元の隣どうしの時間差の絶対値を保ったまま、基準から前後へ並び順に目標時刻を決め直す。締切時刻は各 WP の「目標 → 締切」の差を保つ。目標時刻が空欄の WP は対象外（締切だけ入っていても変えない）。日付を持たないので、差は ±12 時間で折り返し（23:50 → 00:10 は 20 分）、結果は 24 時間で折り返す。計算は core の純粋関数（WaypointTimes）。
- 起動時: 前回のリスト / リストを選ぶ / リストなし、から選択。設定「前回の WP リストを自動で開く」（既定 OFF）が ON なら選ばずに前回のリストを開く。

### 6.6 標高プロファイル（WP ボタン列の下）
- 横軸 = 現在地からの累積水平距離、縦軸 = 標高。現在地 → 次の目標 → その先の目標…を直線で結ぶ（地形なし）。目標は有効かつ未到達の WP で、数は「HUD に描く WP の数」（§6.1）に合わせる。
- 現在地の標高は ALT。NO FIX 中は現在地の点と、そこから次の目標への線をグレーで（最後の値）。
- 標高（ele）のない WP は点を描かず、前後の標高が分かる点の間を破線でつなぐ。片側しか分からなければ線を描かない。
- 縦軸は自動スケール（分かっている標高の範囲。最小の幅 50m、足りなければ中心から広げる）。左に上端・下端の標高の数字。
- 次の WP（の点と、そこへ向かう線）はマゼンタ。中・大では点の上に WP の名前。
- 表示サイズは設定で **OFF / 小 / 中 / 大**（既定 小。高さ 0 / 56 / 88 / 128dp）。
- 座標の計算は core の純粋関数（ProfileBuilder）。

### 6.7 リプレイ
- track.csv 形式を読み込み、元の時刻間隔どおりに Fix を流す（欠損もそのまま再現 → NO FIX の確認に使う）。
- **ファイルの選び方**: 端末の Download フォルダに置いた track.csv を `ACTION_OPEN_DOCUMENT`（ストレージアクセスフレームワーク）で選ぶ。選んだ URI は `takePersistableUriPermission` で永続化して保存し、次回からは選び直さずに再利用する。URI が読めなくなった場合（ファイル削除・権限失効）は選び直してもらう。
- 操作: 再生 / 一時停止は再生の帯の左端、FILE（track.csv を選ぶ）は上部バー（§6.1）。
- **再生の帯**（REPLAY のときだけ、画面の一番下・ナビゲーションバーの上に高さ 36dp で重ねる。WP ボタン列・標高プロファイルの下）: 左から
  - 倍速: [−] ×N [＋]。− で1段遅く、＋ で1段速く（×1 / ×2 / ×5 / ×10 / ×30）。端ではグレーにして押せない。×N は表示だけ。保存せず、起動時と track.csv を読み直したときは ×1。
  - 再生位置のスライダー（シーク）: 指を離したときにシークする。動かしている間は、行き先のトラック時刻を出す。
  - 経過 / 全体の時間（トラックの先頭からの h:mm）。
- **シーク**: トラックの時計をその時刻に合わせ、その時刻までの最後の Fix をすぐ出す。RATE の履歴・通過判定の記録・GPS 方位の保持・PAN はリセットする。
  - 前方へのシーク: シーク元からシーク先までの区間（飛ばした Fix）を、通常どおりの到達判定（到達半径・通過判定）にかけ、トラックが通った WP を到達にする（次の WP はシーク先より先の WP になる）。
  - 後方へのシーク: WP の到達状態は残す。トラックの先頭まで戻したときだけ、すべて未到達に戻す。出し終わったあとも、シークで戻せば再生を続けられる。
- **倍速**: トラックの時計の進み方を変える。Fix はトラックの時刻順にすべて計算に入れ、画面の更新は刻み（50ms）ごとに1回にまとめる。NO FIX・RATE・通過判定・カウントダウン・AUTO 縮尺の待ち時間はトラックの時刻で判定するので、倍速でも ×1 と同じ結果になる（PAN の自動復帰だけは端末の時計）。
- **軌跡**: REPLAY 中は、トラック全体（10m 未満の間隔を間引いたもの）を暗いグレーの細線（1dp）で描き、再生済みの部分（今の Fix まで）をテーマの薄い色の線（2dp）で重ねる（なぞる表示）。WP の線・印より下に描く。
- LIVE と REPLAY は同じ `PositionSource` として差し替える。画面は `NavState`（表示に必要な計算済みの値の集合）だけを見る。
- リプレイ中の「現在時刻」はトラックの時刻を使う（カウントダウン・ETA がログの時刻基準で動くように）。

### 6.8 実センサ・動作
- GPS: FusedLocation ではなく `LocationManager` の GPS プロバイダ（依存を増やさないため）。1秒間隔。
  - Location → Fix: 値がないもの（hasSpeed などが false）は null。速度 0 で方位精度がなければ方位 null（track.csv と同じ扱い）。
- コンパス: 回転ベクトルセンサ等から方位を求め、`GeomagneticField` で磁気偏角を補正して真北基準にする。
  - `TYPE_ROTATION_VECTOR`。なければ加速度＋地磁気、それもなければコンパスなし（HYBRID は保持 GPS 方位）。
  - 姿勢は重力方向から自動判定: 画面の傾きが 55° 以上で立て置き（車載ホルダー）、35° 以下で平置き、その間は前の姿勢を保つ。立て置きは `remapCoordinateSystem(AXIS_X, AXIS_Z)` で端末の背面が向く方向を機首方位にする。
  - 偏角の位置: 今の Fix → 最後に分かっている位置 → なし（偏角 0）。偏角が分からないときは数値の表示の HDG の横に **MAG**、センサの精度が低いときは **CAL** の印を付ける。
  - 角度は単位ベクトルで平滑化する（0/360 をまたいでも正しく扱う）。
- 標高 = GPS 楕円体高 − 固定オフセット（設定、既定 36m 目安）。
- フォアグラウンドのみで動作。位置取得はフォアグラウンドサービス（`foregroundServiceType="location"`）、通知は固定表示「NavHUD 動作中」のみ。通知アイコンは単色の線画（ARC の弧・自機・次の WP）。画面の onStart で開始、onStop で停止。バックグラウンドの位置情報権限は要求しない。
- 権限: 位置情報（正確な位置）が拒否されたら画面中央に案内を出し、REPLAY は使えるようにする。通知の権限（Android 13 以降）は拒否されても動作を続ける。
- LIVE / REPLAY: 上部バーの INPUT をタップして切り替える（選んだ方を保存し、次の起動もそれで始める。初回は LIVE）。切替時は RATE の履歴と通過判定の記録をリセットし、WP の到達状態は残す。リプレイ操作は REPLAY のときだけ出す。
- **LIVE の軌跡**: 起動してからの軌跡を、テーマの薄い色の細線（1.5dp）で描く。メモリに持つだけで保存しない。前の点から 5m 以上動いたときだけ点を足し、上限 5,000 点（超えたら古い方から捨てる）。LIVE ⇔ REPLAY を切り替えても消さない（REPLAY 中は描かない）。
- 画面常時点灯（FLAG_KEEP_SCREEN_ON）は設定で ON/OFF（既定 ON）。
- エミュレータでの確認: `tools/track2gpx.ps1` で track.csv から GPX（trkpt に時刻付き）を作り（出力は sample/、git 管理外）、Extended Controls → Location で再生する。

### 6.10 PAN（ドラッグで先の WP を見る）
- 地図をドラッグすると、表示を平行移動する（指の動きと同じ向きに地図が動く）。縮尺はそのまま（＋ / − は効く）。
- PAN 中の ＋ / − は AUTO を OFF にしない（縮尺は PAN の間だけ変わる）。現在地に戻ったら、AUTO が ON なら待たずに縮尺を決め直す。AUTO が OFF なら PAN 中に変えた縮尺のまま。
- PAN 中は、操作列の縮尺の表示が **PAN**（黄）になり、＋ のすぐ下（操作列の一番下）に **現在地**（現在地の表示に戻る）ボタンを出す（− / RNG / ＋ の位置は変えない）。縮尺の AUTO は止める（戻ったら再開）。
- ARC では、ドラッグを始めた時点の機首方位で地図の向きを固定する（North Up は北が上のまま）。
- PAN 中の描き方: 距離環は自機を中心に全周。方位目盛りは ARC と同じ枠（上は回避枠の上端、左右は描画の枠の左右端）と、PAN の中心から各方位へ引いた線との交点。PAN の中心は、横は描画の枠の左右中央、縦は回避枠の縦中央に置く。ラバーライン・上部の三角・方位線は描かない。自機の記号は固定した向きから見た機首方位を指す。画面外の矢印は PAN の中心から見た方向で、距離は自機から。
- 操作（ドラッグ、＋ / −、WP ボタンの長押し）がないまま **15 秒**（設定で 5〜60 秒）たつと、自動的に現在地の表示へ戻る。時間は端末の時計で数える（リプレイの一時停止中も戻る）。
- WP ボタンの長押しでも、その WP を PAN の中心にした PAN になる。
- 表示モードを切り替えたとき、LIVE ⇔ REPLAY を切り替えたとき、リプレイを巻き戻したときも PAN をやめる。

## 7. WP ファイル形式
### 7.1 CSV（メイン。インポート/エクスポート）
```
lat,lon,ele,name,target_time,deadline_time,enabled,radius
34.69370,135.50230,15,大阪駅,09:30,10:00,1,200
```
- 列はヘッダ名で参照する（順序・追加列・末尾列欠けに強く）。必須は lat, lon。
- 時刻はローカル `H:mm` / `HH:mm` / `H:mm:ss` / `HH:mm:ss`。空欄可。ele 空欄可。
- `enabled`（任意の列）: 1 = 有効、0 = 無効。列がない・空欄なら有効とみなす。**reached は保存しない。**
- `radius`（任意の列）: この WP の到達半径 [m]。空欄・列なしなら全体の設定（NavSettings の到達半径）。0 以下・数値でなければ読めない行。
- 名前などにカンマ・`"`・改行が含まれる場合は `"..."` で囲み、`"` は `""` にする（RFC 4180）。
- 読めない行はスキップして件数を返す（例外にしない）。
- エクスポートも同じ形式（上の8列）。
- **Excel 互換（Excel で編集される前提）**:
  - 書き出しは UTF-8 の BOM 付き、改行は CRLF。
  - 読み込みの文字コード: BOM があれば UTF-8。なければ UTF-8 として厳密に読み、失敗したら Windows-31J（Shift_JIS）で読み直す。
  - 時刻は上の4形式をすべて受け付ける（Excel が 09:30 を 9:30 や 9:30:00 に変えるため）。
  - 数値の前後の空白、末尾の空行、CRLF / LF の混在を許容する。

### 7.2 GPX（サブ。インポートのみ）
- `<wpt lat lon>`、`<name>`、`<ele>`、`<time>` = 目標時刻、`<extensions><deadline>` = 締切時刻。
- `<time>` / `<deadline>` は ISO 8601 の日時なら端末のタイムゾーンの時刻に変換し、`H:mm(:ss)` だけならそのまま使う。
- lat / lon が読めない `<wpt>` はスキップして件数を返す。

### 7.3 座標の貼り付け
- Google マップのピン座標 `34.69370, 135.50230` 形式。前後の空白、カンマ後のスペースなしに対応。
- 範囲外（緯度 ±90、経度 ±180 を超える）や形式違いは読めないとして扱う。
- DMS・URL・複数行は未対応（§10）。
