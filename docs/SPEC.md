# NavHUD 仕様書

## 1. 概要
- アプリ名: ナビHUDアプリ / NavHUD
- 用途: 地上（自動車・徒歩など）でのナビゲーション表示。航空機の ND/HSI 風の黒背景・線画。
- ウェイポイント(WP)の座標リストに対して、自機位置・方位・距離・到着予定などを表示する。
- 地図は持たない（背景画像は §8 の低優先機能）。記録はしない。フォアグラウンドでのみ動作。

## 2. サンプルデータ（track.csv）
自作GPSロガーの生データ。リプレイ用インポート形式であり、開発・テストのサンプル。

### 2.0 置き場所と git の扱い
- track.csv は**意図的に git 管理外**。`/sample` は `.gitignore` で除外したままにする。
- 開発機では `sample/session_20260814_075234/track.csv` に置く。
- track.csv を使う単体テストは、ファイルがなければ JUnit の `Assume` でスキップする（失敗にしない）。
- 実機でのリプレイは、端末の Download フォルダに置いた track.csv を選んで使う（§6.7）。

### 2.1 列
```
utc_iso8601, epoch_ms, elapsed_realtime_ns, provider, latitude, longitude,
altitude_ellipsoid_m, horizontal_acc_m, vertical_acc_m, speed_mps, speed_acc_mps,
bearing_deg, bearing_acc_deg, gdop, pdop, hdop, vdop, tdop, is_mock
```
例: `2026-08-13T22:52:35.000Z,1786661555000,1947490778078885,gps,33.47406592,133.00034867,1320.71875,4.58744,4.8811636,14.48,1.8681006,62.4,4.183182,1.56,1.31,0.72,1.10,0.84,false`

### 2.2 内容と癖（実装で考慮すること）
- 四国山間部、2026-08-13T22:52:35Z〜2026-08-14T02:02:00Z、11,172 行、基本1秒間隔、総距離 約74.23km、高度 281〜1443m（楕円体高）。
- **停止中は `speed_mps=0, bearing_deg=0, bearing_acc_deg=0` と書かれる**（3,243行）。これは「方位なし」の意味であり、北向きではない。
- 停止中も位置は数mジッタする（停止が全体の約1/3）。位置差分から方位・距離を出すとジッタを拾う。
- **記録の欠損が9か所**（間隔 > 1.5秒）。最長62秒（01:06:52Z→01:07:54Z、約1.17km 移動）、続けて48秒（01:07:56Z→01:08:44Z）。
- **欠損直後の10行は DOP が欠けて列が1つ少ない**（`tdop` 位置に "false"、`is_mock` なし）。列は位置でなくヘッダ名で参照すること。
- この地域のジオイド高 ≒ 36m（楕円体高 − 36 ≒ 標高）。

## 3. データ型（core/model）

### 3.1 Fix（位置1件。実機GPSとリプレイで共通）
| フィールド | 型 | 説明 |
|---|---|---|
| timeMs | Long | UTC epoch ms |
| lat, lon | Double | 度 |
| altRawM | Double? | 楕円体高（生値）。表示時に標高オフセットを引く |
| speedMps | Float? | 対地速度 |
| bearingDeg | Float? | 進行方位（真北, 0..360）。**null = 方位なし** |
| horizAccM | Float? | 水平精度 |

### 3.2 Waypoint
| フィールド | 型 | 説明 |
|---|---|---|
| name | String | |
| lat, lon | Double | |
| eleM | Double? | 標高 |
| targetTime | LocalTime? | 目標時刻（ローカル） |
| deadlineTime | LocalTime? | 締切時刻（ローカル） |
| enabled | Boolean | 既定 true |
| reached | Boolean | 既定 false |

### 3.3 enum
- `SourceMode { HYBRID, GPS, COMPASS }` — ユーザーが選ぶ方位ソース
- `HeadingSrc { GPS, COMPASS, NONE }` — 実際に使われている方位ソース

### 3.4 ソースのインターフェース
```kotlin
interface PositionSource { val fixes: Flow<Fix> }        // Live GPS / Replay
interface HeadingSource  { val headingDeg: Flow<Float> } // コンパス（真北補正済み）
```

## 4. トラックCSVの読み込み（core/io）
- 1行目ヘッダ。UTF-8 BOM があれば除去。列はヘッダ名で引く（順序・追加列・末尾列欠けに強く）。
- 必須: `latitude`, `longitude`, 時刻（`epoch_ms` 優先、なければ `utc_iso8601` を ISO8601 解析）。
- 任意: `altitude_ellipsoid_m`→altRawM, `speed_mps`, `bearing_deg`, `bearing_acc_deg`, `horizontal_acc_m`。空欄は null。
- **方位の有効判定**: `bearing_acc_deg` 列がある場合は `bearing_acc_deg > 0` のときだけ有効。列がない場合は speed が null または > 0 なら有効。無効なら bearingDeg = null。
- 必須項目が読めない行はスキップし、スキップ数を返す（例外にしない）。
- 戻り値: `(fixes: List<Fix>, skippedLines: Int)`

## 5. 計算コア（core/geo, core/nav）

### 5.1 地理計算
- 距離: 大圏距離（haversine, 地球半径 6,371,000m）
- 方位: 初期方位（真北基準 0..360）
- 角度差: from→to の最短回転 (-180, 180]
- 平面近似: 自機を原点とする正距円筒（東m, 北m）。数十km以内で使う。
- 画面座標: 上方向を `upDeg` とする回転（Heading Up は upDeg = 機首方位、North Up は 0）。
  `right = e·cos(h) − n·sin(h)`, `fwd = e·sin(h) + n·cos(h)`

### 5.2 方位選択（HeadingSelector）
- 方位ソースの既定は **GPS**（実機テストで、車内ではコンパスが不安定だったため）。HYBRID と COMPASS は歩行用に残す。
- GPS 方位が「使える」条件: bearingDeg ≠ null かつ（水平精度が null または ≤ 15 m）かつ（方位の精度が null または ≤ 20°。値を出している端末のみ）。
- **GPS 方位の保持（ヒステリシス）**: 速度が「保持開始速度」（既定 2.0 m/s ≒ 7km/h）未満で保持に入り、「保持解除速度」（既定 3.0 m/s ≒ 11km/h）を超え、かつ GPS 方位が使えるときに GPS 方位に戻る。
  - 保持する値は、保持解除速度以上で走っていた間の最後の方位（減速中のふらついた値は使わない）。
  - 保持中は下部パネルの HDG の付記を **HLD** にする。HLD は速度による保持だけを表す。走行中に方位の精度が悪い Fix が混ざったときは、HLD にせず直前の使えた GPS 方位のまま。
  - 状態は Fix が来たときだけ更新する（tick やコンパスの値では変えない）。
- GPS モード: 今の GPS 方位。保持中は保持した方位（HLD）。どちらもなければ NONE。
- COMPASS モード: コンパス値（なければ NONE）。
- HYBRID: 今の GPS 方位 → （保持中は）コンパスが CAL でなければコンパス → 保持した GPS 方位 → CAL のコンパス → NONE。
- 値はすべて NavSettings に置く（設定画面 §6.9 で変えられる）。
- 切替時のスムージングはオプション（後回し可）。

### 5.3 RATE（移動距離・高度差・平均速度）
- 窓: 10 / 30 / 60 秒（上部の RATE 行で切替）。平均速度は ETA にも使う（§5.4）。
- 直近の Fix を保持（最大窓 + 余裕分）。窓の起点 = 最新時刻 − 窓秒。起点以前で最も新しい Fix を base とする。
- base がない、または base が起点より 2 秒を超えて古い（= 欠損）→ **null（表示 "---"）**。
- 距離 = base→最新の各区間の和。区間は両端の速度があれば **速度の台形積分**（停止中のジッタを拾わない）、速度がない区間と **間隔 > 2秒の欠損区間は直線距離**。
- 高度差 = 最新 altRawM − base altRawM。平均速度 = 距離 / (最新時刻 − base 時刻)。

### 5.4 ウェイポイント
- 次の目標 = enabled かつ未 reached のうち番号（リスト順）最小。なければ null。
- 自動到達: 次の目標との距離 ≤ 到達半径（50/100/200/500m 選択）で reached = true → 自動的に次へ。
- 通過判定（オプション設定、既定オン）: 最接近後に離れていったら到達とみなす。到達半径の判定の補助として働く。
  - 対象は次の WP のみ。最接近距離は、隣り合う Fix を結んだ線分と WP の最短距離で求める（記録の欠損中に通過しても拾える）。
  - 最接近距離 ≤ 300 m のあと、距離が「最接近距離 + 50 m」以上の状態が 5 秒続いたら到達。
  - WP ごとの到達半径（§7.1 の radius）があれば、最接近距離の上限は max(300 m, 半径 × 3)。到達半径の判定もその WP の半径を使う。
  - 次の WP が変わったら（到達・手動トグル・並べ替えなど）最接近の記録をリセットする。
  - 3つの値とオン/オフは設定画面（§6.9）で変えられる（つづら折りや並行道路で誤判定しうるため）。誤判定は手動トグルで戻せる。
- 手動トグル: 指定 WP の reached を反転。**個別で他の WP に連動しない**。無効 WP は操作不可。
- ETA = 現在時刻 + 直線距離 / 平均速度（§5.3 の RATE の窓）。平均速度 < 0.5 m/s なら null。
  - 履歴が窓に足りない（走り始め・欠損のあと）ときは、窓の中にある分の平均速度を使う。ある分が 10 秒未満なら null。
- 目標/締切カウントダウン: 対象時刻 − 現在時刻（ローカル時刻、秒）。過ぎたら負。日付を持たないため差が ±12時間を超えたら 24時間で折り返す。

### 5.5 NO FIX
- 最後の Fix から設定秒数（既定 10 秒）を超えたら NO FIX。一度も測位していなければ NO FIX（起動直後の未測位・途切れた後・リプレイの欠損、どれも同じ NO FIX）。
- ログの欠損検出（テスト・デバッグ用）: 隣接 Fix の間隔 > 1.5 秒を欠損とする。

## 6. 画面・動作

### 6.1 メイン画面（共通）
- 黒背景、線画。自機マーカー、ラバーライン、上部の三角マーカー。
- **画面の配分**（縦、上から）: 上部バー 38dp / 情報欄 74dp / **地図**（残り全部）/ 標高プロファイル（§6.6。OFF 0・小 56・中 88・大 128dp）/ 下部パネル 125dp。背の高い端末では地図だけが伸びる。
  - 地図の上に **重ねる** もの（半透明の黒の背景）: 右端に **操作列**（幅 60dp。＋ / RNG / − / 現在地 / ▶ / FILE）、下端に **横並びの WP ボタン列**（高さ 48dp、§6.4。上部バーの WP で表示 / 非表示）、REPLAY のときだけその上に **リプレイの帯**（高さ 40dp、§6.7）。
  - **描画の枠** = 地図の全体（画面の全幅）。距離環・方位線・方位目盛りはこの枠に描き、重ねた部品の下にもかかる（目盛りの一部が隠れるのは許容）。
  - **避ける枠** = 描画の枠から、重ねた部品（操作列・リプレイの帯・WP ボタン列）を除いた領域。画面外の矢印・WP の印と名前はこの内側（縁から 22dp）に置き、AUTO 縮尺の「収まるか」もこの枠で判定する。
- 上部バー: **HDG**（方位ソースの選択 HYBRID / GPS / COMPASS）、WP ボタン（WP ボタン列の表示/非表示）、表示モード（ARC / North Up）、**⚙**（設定画面 §6.9）。バーの空いている所の長押しは開発用画面。
- 数値表示（情報欄）: TIME（ローカル）、LAT/LON、ALT（楕円体高 − 標高オフセット）、RATE（10/30/60s 切替。移動距離と高度差）。
- 下部パネル: HDG（値の横に実際に使っている方位ソースを小さく付記: `053° GPS` / `053° CMP`。コンパスの印 CAL / MAG もここに黄色で）、GS、NEXT WP 方位/距離、ETA、目標時刻カウントダウン、締切カウントダウン（超過で色変更）、**INPUT**（LIVE / REPLAY。タップで切替）。
- WP: 登録順に線で結ぶ。無効 WP はグレー破線。画面外の WP は避ける枠の縁に方位方向の矢印＋距離。
  - 描く WP は、次の WP から先の目標（有効かつ未到達）N 個（設定、既定 3、1〜10）と、直前に到達した WP 1つ（暗め）。目標の間にある無効 WP は数えずにグレーで描く。線もこの範囲だけ。
- 距離環: 間隔は縮尺の段の 1/2。文字は、1000m 未満は m の数字だけ（`25` / `50` / `100` / `250` / `500`）、1000m 以上は k（`1k` / `2.5k` / `5k` / `10k` / `25k`）。方位目盛りの文字より小さく薄い色。方位目盛りの文字と重なる距離環の文字は出さない。
- 文字の重なり: 画面外の矢印の文字は、方位目盛り・距離環の文字、自機の記号、上部の方位マーカー、画面内の WP の印と名前、その矢印自身、先に置いた矢印の文字と重ならない位置に置く（自機側・線と直角の両側へ1行ずつずらして探す。最大3行）。WP の名前は印の上、自機の記号と重なるなら下、それでも重なるなら描かない。到達済みの WP は下へ逃がさず、自機の記号と重なるなら名前を描かない（PAN 中も同じ）。
- 画面外の矢印（三角）が方位目盛り・距離環の文字に重なるときは、避ける枠の縁に沿ってずらす（三角の大きさずつ両側へ、最大4段）。 ARC の上部中央の方位マーカー（三角）とラバーラインの周り（マーカーの左右 2 つ分の幅）に来るときも、横にずらす。
- NO FIX 時: 避ける枠の中央にメッセージ枠。最後の値はグレーで表示し続ける。
- **当面の扱い（§10 の未決定事項）**: 画面の向きは縦固定。
- **縮尺（ARC / North Up 共通）**: 段階的な縮尺 **50m / 100m / 200m / 500m / 1km / 2km / 5km / 10km / 20km / 50km**（ARC では基準の距離環が画面の左右端に接する距離、North Up では最外周の距離環）。使う段は設定で選ぶ（既定 100m〜20km）。起動時は 1km。
  - 操作列の上から **＋ / 縮尺の表示 / −**（52dp 角）。縮尺の表示は2行（`AUTO` / `RNG` / `PAN` と、段 `500m` / `1km`）で、タップすると AUTO の ON / OFF。
  - **AUTO**（既定 ON）: 次の WP を画面座標に投影したとき、避ける枠の内側（縁から 22dp、さらに余白 16dp）に収まる最小の有効段。どの段にも収まらなければ最大の段。ARC / North Up で同じ関数（ARC は機首方位と自機の位置を反映）。広げる方向はすぐ、狭める方向は 5 秒続いてから切り替える。＋ / − を押したら AUTO は OFF。PAN 中（§6.10）は止める。
  - 画面の大きさがまだ分からないときだけ、距離で判定する（次の WP が「縮尺 × 0.9」以内）。対地速度も受け取るが、今は使わない（将来「速度に応じた縮尺」のため）。
- 色は航空機の ND の慣習に合わせる: 背景は黒、薄い方位線は暗いグレー。次の WP とそこへの線はマゼンタ、無効 WP はグレーの破線、到達済み WP は暗めの色。警告（NO FIX、締切超過）は黄〜赤。NO FIX 中の値はグレー。
  - **色テーマ**（設定）: 基本色（目盛り・距離環・文字・自機・有効 WP）を **白 / 緑 / 琥珀** から選ぶ（既定 白）。マゼンタ・黄 / 赤・グレーはテーマによらず固定。色の定義は ui/HudColors の1か所。

### 6.2 ARC モード（Heading Up）
- 前方 180°。自機は **画面の横中央**。高さは避ける枠の下端（WP ボタン列の上端。REPLAY ではリプレイの帯の上端）から、設定で **標準（110dp）/ 高め（170dp）**。高めでは後方の WP・矢印に余裕ができる（AUTO も後方の WP を狭い段で収められる）。
- 縮尺: 基準距離環（縮尺の段）が画面の左右端にちょうど接するように拡大。
- 方位目盛りは同心円に沿わせない。自機から各方位へ引いた線と **描画の枠（画面）の縁** との交点に置く。画面からはみ出す分は切れてよく、右端の目盛りは操作列の下に隠れてよい。
- 30°ごとに薄い方位線を引く。

### 6.3 North Up モード
- 全周コンパスカード（HSI 風）。自機は、横は画面の中央、縦は避ける枠の中央。最外周の距離環は、画面の幅と避ける枠の高さの小さい方に収める。目盛りは最外周の距離環の外側。

### 6.4 WP ボタン列（地図の下端に重ねる、横並び）
- 自機の下のスペース（地図の下端、高さ 48dp）に横並び。左端に固定の「WP設定」ボタン（幅 64dp）、その右は左から WP1, WP2, WP3…（左右にスクロール）。
- 一度に見せるボタンの数を設定で選ぶ（既定 4、3〜6）。ボタンの幅はこの数で決まる。次の WP が変わったら、それが中央に来るよう自動でスクロールする（端では寄せきれない分だけ端に寄る）。
- **タップ**: 到達済みを個別にトグル（色反転で表示）。無効 WP はグレーで押せない。
- **長押し**: その WP を地図の中心にした PAN にする（§6.10）。無効 WP も長押しは効く。

### 6.5 WP設定画面
- ≡ のドラッグで並べ替え、有効/無効スイッチ、編集（名前、"lat, lon" の1フィールド、標高、目標時刻、締切時刻）、追加、貼り付け、インポート、エクスポート。
- 貼り付け: Google マップでピンを立ててコピーした座標 `34.69370, 135.50230` 形式。
- 編集の項目に **到達半径**（m、空欄で全体の設定）。
- **逆順にする**: リストの順番を反転し、到達済みをすべて解除する（確認のダイアログを出す）。
- **時刻を一括調整**: 基準の WP（目標時刻の入った WP から選ぶ。既定は先頭の、有効で目標時刻の入った WP）と、その新しい目標時刻を入力する。目標時刻の入った WP（無効 WP も含む）を並び順に取り出し、元の隣どうしの時間差の絶対値を保ったまま、基準から前後へ並び順に目標時刻を決め直す。締切時刻は各 WP の「目標 → 締切」の差を保つ。目標時刻が空欄の WP は対象外（締切だけ入っていても変えない）。日付を持たないので、差は ±12 時間で折り返し（23:50 → 00:10 は 20 分）、結果は 24 時間で折り返す。計算は core の純粋関数（WaypointTimes）。
- 起動時: 前回のリスト / リストを選ぶ / リストなし、から選択。設定「前回の WP リストを自動で開く」（既定 OFF）が ON なら選ばずに前回のリストを開く。

### 6.6 標高プロファイル（WP ボタン列の下）
- 横軸 = 現在地からの累積水平距離、縦軸 = 標高。現在地 → 次の目標 → その先の目標…を直線で結ぶ（地形なし）。目標は有効かつ未到達の WP で、数は「HUD に描く WP の数」（§6.1）に合わせる。
- 現在地の標高は ALT。NO FIX 中は現在地の点と、そこから次の目標への線をグレーで（最後の値）。
- 標高（ele）のない WP は点を描かず、前後の標高が分かる点の間を破線でつなぐ。片側しか分からなければ線を描かない。
- 縦軸は自動スケール（分かっている標高の範囲。最小の幅 50m、足りなければ中心から広げる）。左に上端・下端の標高の数字。
- 次の WP（の点と、そこへ向かう線）はマゼンタ。中・大では点の上に WP の名前。
- 表示サイズは設定で **OFF / 小 / 中 / 大**（既定 小。高さ 0 / 56 / 88 / 128dp）。
- 座標の計算は core の純粋関数（ProfileBuilder）。

### 6.7 リプレイ
- track.csv 形式を読み込み、元の時刻間隔どおりに Fix を流す（欠損もそのまま再現 → NO FIX の確認に使う）。
- **ファイルの選び方**: 端末の Download フォルダに置いた track.csv を `ACTION_OPEN_DOCUMENT`（ストレージアクセスフレームワーク）で選ぶ。選んだ URI は `takePersistableUriPermission` で永続化して保存し、次回からは選び直さずに再利用する。URI が読めなくなった場合（ファイル削除・権限失効）は選び直してもらう。
- 操作: 再生 / 一時停止と FILE（track.csv を選ぶ）は操作列の下（§6.1）。
- **リプレイの帯**（REPLAY のときだけ、WP ボタン列の上に高さ 40dp で重ねる）: 左から
  - 倍速ボタン: タップで ×1 → ×2 → ×5 → ×10 → ×30 → ×1。保存せず、起動時と track.csv を読み直したときは ×1。
  - 再生位置のスライダー（シーク）: 指を離したときにシークする。動かしている間は、行き先のトラック時刻を出す。
  - 経過 / 全体の時間（トラックの先頭からの h:mm）。
- **シーク**: トラックの時計をその時刻に合わせ、その時刻までの最後の Fix をすぐ出す。RATE の履歴・通過判定の記録・GPS 方位の保持・PAN はリセットする。
  - 前方へのシーク: シーク元からシーク先までの区間（飛ばした Fix）を、通常どおりの到達判定（到達半径・通過判定）にかけ、トラックが通った WP を到達にする（次の WP はシーク先より先の WP になる）。
  - 後方へのシーク: WP の到達状態は残す。トラックの先頭まで戻したときだけ、すべて未到達に戻す。出し終わったあとも、シークで戻せば再生を続けられる。
- **倍速**: トラックの時計の進み方を変える。Fix はトラックの時刻順にすべて計算に入れ、画面の更新は刻み（50ms）ごとに1回にまとめる。NO FIX・RATE・通過判定・カウントダウン・AUTO 縮尺の待ち時間はトラックの時刻で判定するので、倍速でも ×1 と同じ結果になる（PAN の自動復帰だけは端末の時計）。
- **軌跡**: REPLAY 中は、トラック全体（10m 未満の間隔を間引いたもの）を暗いグレーの細線（1dp）で描き、再生済みの部分（今の Fix まで）をテーマの薄い色の線（2dp）で重ねる（なぞる表示）。WP の線・印より下に描く。
- LIVE と REPLAY は同じ `PositionSource` として差し替える。画面は `NavState`（表示に必要な計算済みの値の集合）だけを見る。
- リプレイ中の「現在時刻」はトラックの時刻を使う（カウントダウン・ETA がログの時刻基準で動くように）。

### 6.8 実センサ・動作
- GPS: FusedLocation ではなく `LocationManager` の GPS プロバイダ（依存を増やさないため）。1秒間隔。
  - Location → Fix: 値がないもの（hasSpeed などが false）は null。速度 0 で方位精度がなければ方位 null（track.csv と同じ扱い）。
- コンパス: 回転ベクトルセンサ等から方位を求め、`GeomagneticField` で磁気偏角を補正して真北基準にする。
  - `TYPE_ROTATION_VECTOR`。なければ加速度＋地磁気、それもなければコンパスなし（HYBRID は保持 GPS 方位）。
  - 姿勢は重力方向から自動判定: 画面の傾きが 55° 以上で立て置き（車載ホルダー）、35° 以下で平置き、その間は前の姿勢を保つ。立て置きは `remapCoordinateSystem(AXIS_X, AXIS_Z)` で端末の背面が向く方向を機首方位にする。
  - 偏角の位置: 今の Fix → 最後に分かっている位置 → なし（偏角 0）。偏角が分からないときは下部パネルの HDG の横に **MAG**、センサの精度が低いときは **CAL** の印を付ける。
  - 角度は単位ベクトルで平滑化する（0/360 をまたいでも正しく扱う）。
- 標高 = GPS 楕円体高 − 固定オフセット（設定、既定 36m 目安）。
- フォアグラウンドのみで動作。位置取得はフォアグラウンドサービス（`foregroundServiceType="location"`）、通知は固定表示「NavHUD 動作中」のみ。通知アイコンは単色の線画（ARC の弧・自機・次の WP）。画面の onStart で開始、onStop で停止。バックグラウンドの位置情報権限は要求しない。
- 権限: 位置情報（正確な位置）が拒否されたら画面中央に案内を出し、REPLAY は使えるようにする。通知の権限（Android 13 以降）は拒否されても動作を続ける。
- LIVE / REPLAY: 下部パネルの INPUT をタップして切り替える（選んだ方を保存し、次の起動もそれで始める。初回は LIVE）。切替時は RATE の履歴と通過判定の記録をリセットし、WP の到達状態は残す。リプレイ操作は REPLAY のときだけ出す。
- **LIVE の軌跡**: 起動してからの軌跡を、テーマの薄い色の細線（1.5dp）で描く。メモリに持つだけで保存しない。前の点から 5m 以上動いたときだけ点を足し、上限 5,000 点（超えたら古い方から捨てる）。LIVE ⇔ REPLAY を切り替えても消さない（REPLAY 中は描かない）。
- 画面常時点灯（FLAG_KEEP_SCREEN_ON）は設定で ON/OFF（既定 ON）。
- エミュレータでの確認: `tools/track2gpx.ps1` で track.csv から GPX（trkpt に時刻付き）を作り（出力は sample/、git 管理外）、Extended Controls → Location で再生する。

### 6.9 設定画面
- 入口: 上部バーの **⚙**。開発用画面はバーの長押しのまま。
- 変更はすぐ画面に反映し、そのたびに保存する（SharedPreferences。NavSettings の全項目と INPUT）。「設定を初期値に戻す」ボタンあり。
- 構成:
  - **表示**: 表示モード（ARC / North Up）、色テーマ（白 / 緑 / 琥珀）、ARC の自機の位置（標準 / 高め）、標高プロファイル（OFF / 小 / 中 / 大）、標高オフセット
  - **方位**: 方位ソース、保持に入る / 解く速度、GPS の水平精度の上限、GPS の方位の精度の上限
  - **縮尺**: 使う段（1つ以上。50m〜50km）、起動時の縮尺、起動時に AUTO、AUTO で狭めるまでの時間、PAN から現在地へ戻るまでの時間
  - **WP**: 到達半径（全体）、通過判定のオン / オフと3つの値、WP ボタン列に見せる数（3〜6）、HUD に描く WP の数
  - **測位・入力**: INPUT（LIVE / REPLAY）、NO FIX とみなす時間、RATE の窓
  - **その他**: 画面常時点灯、前回の WP リストを自動で開く
- 読めない保存値（範囲外・古い版の値）は、その項目だけ初期値に戻す。

### 6.10 PAN（ドラッグで先の WP を見る）
- 地図をドラッグすると、表示を平行移動する（指の動きと同じ向きに地図が動く）。縮尺はそのまま（＋ / − は効く）。
- PAN 中の ＋ / − は AUTO を OFF にしない（縮尺は PAN の間だけ変わる）。現在地に戻ったら、AUTO が ON なら待たずに縮尺を決め直す。AUTO が OFF なら PAN 中に変えた縮尺のまま。
- PAN 中は、操作列の縮尺の表示が **PAN**（黄）になり、その下に **現在地**（現在地の表示に戻る）ボタンを出す。縮尺の AUTO は止める（戻ったら再開）。
- ARC では、ドラッグを始めた時点の機首方位で地図の向きを固定する（North Up は北が上のまま）。
- PAN 中の描き方: 距離環は自機を中心に全周。方位目盛りは描画の枠（画面）の縁（PAN の中心から各方位へ引いた線との交点）。PAN の中心は、横は画面の中央、縦は避ける枠の中央に置く。ラバーライン・上部の三角・方位線は描かない。自機の記号は固定した向きから見た機首方位を指す。画面外の矢印は PAN の中心から見た方向で、距離は自機から。
- 操作（ドラッグ、＋ / −、WP ボタンの長押し）がないまま **15 秒**（設定で 5〜60 秒）たつと、自動的に現在地の表示へ戻る。時間は端末の時計で数える（リプレイの一時停止中も戻る）。
- WP ボタンの長押しでも、その WP を PAN の中心にした PAN になる。
- 表示モードを切り替えたとき、LIVE ⇔ REPLAY を切り替えたとき、リプレイを巻き戻したときも PAN をやめる。

## 7. WP ファイル形式
### 7.1 CSV（メイン。インポート/エクスポート）
```
lat,lon,ele,name,target_time,deadline_time,enabled,radius
34.69370,135.50230,15,大阪駅,09:30,10:00,1,200
```
- 列はヘッダ名で参照する（順序・追加列・末尾列欠けに強く）。必須は lat, lon。
- 時刻はローカル `H:mm` / `HH:mm` / `H:mm:ss` / `HH:mm:ss`。空欄可。ele 空欄可。
- `enabled`（任意の列）: 1 = 有効、0 = 無効。列がない・空欄なら有効とみなす。**reached は保存しない。**
- `radius`（任意の列）: この WP の到達半径 [m]。空欄・列なしなら全体の設定（NavSettings の到達半径）。0 以下・数値でなければ読めない行。
- 名前などにカンマ・`"`・改行が含まれる場合は `"..."` で囲み、`"` は `""` にする（RFC 4180）。
- 読めない行はスキップして件数を返す（例外にしない）。
- エクスポートも同じ形式（上の8列）。
- **Excel 互換（Excel で編集される前提）**:
  - 書き出しは UTF-8 の BOM 付き、改行は CRLF。
  - 読み込みの文字コード: BOM があれば UTF-8。なければ UTF-8 として厳密に読み、失敗したら Windows-31J（Shift_JIS）で読み直す。
  - 時刻は上の4形式をすべて受け付ける（Excel が 09:30 を 9:30 や 9:30:00 に変えるため）。
  - 数値の前後の空白、末尾の空行、CRLF / LF の混在を許容する。

### 7.2 GPX（サブ。インポートのみ）
- `<wpt lat lon>`、`<name>`、`<ele>`、`<time>` = 目標時刻、`<extensions><deadline>` = 締切時刻。
- `<time>` / `<deadline>` は ISO 8601 の日時なら端末のタイムゾーンの時刻に変換し、`H:mm(:ss)` だけならそのまま使う。
- lat / lon が読めない `<wpt>` はスキップして件数を返す。

### 7.3 座標の貼り付け
- Google マップのピン座標 `34.69370, 135.50230` 形式。前後の空白、カンマ後のスペースなしに対応。
- 範囲外（緯度 ±90、経度 ±180 を超える）や形式違いは読めないとして扱う。
- DMS・URL・複数行は未対応（§10）。

## 8. 背景地図（優先度低・最後）
- PNG/JPEG ＋ 同名の JSON: `imageFile, imageWidthPx, imageHeightPx, topLeft, bottomRight, rotationDeg`。QGIS で作成する前提。
- 基準点はリストで持つ（将来 4 点対応）。複数画像を現在地で自動切替。

### 計算
- 緯度 1 度の距離 ≈ 111,195m（±1）。
- 方位: 北 0°、東 ≈ 90°、南 180°、西 ≈ 270°。
- 角度差: (350→10) = +20、(10→350) = −20、(0→180) = 180。
- 平面近似の距離と haversine の差 < 2m（約3km の範囲で）。
- 回転: 機首 090 のとき、東 100m の点 → 前方 100m、北 100m の点 → 左 100m。North Up ではそのまま。
- 方位選択: HYBRID で移動中かつ高精度 → GPS。低速 / 方位 null → COMPASS。低精度は、直前に使える GPS 方位がなければ COMPASS、あれば直前の GPS 方位のまま（1秒ごとに GPS ⇔ COMPASS が入れ替わるのを避けるため）。GPS モードで停止 → 最後の GPS 方位を保持（HLD）。入力なし → NONE。
- RATE: 10m/s 等速・毎秒 1m 上昇 → RATE(60) 距離 600m、高度差 60m、平均 10m/s。RATE(10) = 100m。20 秒分しか履歴がなければ RATE(30) = null。
- WP: [無効, 到達済, 未到達, 未到達] → 次 = index 2。約33m 地点で半径 50m なら到達して次は index 3、半径 20m なら未到達。手動トグルは個別で、無効 WP には効かない。
- ETA: 1000m / 10m/s → +100 秒。0.2m/s → null。窓 60 秒に対して履歴 9 秒 → null、10 秒 → その 10 秒の平均速度で出す。
- AUTO 縮尺（段 50m〜50km、地図 720×690 px・密度 1.7・右の操作列 60dp・下の WP ボタン列 48dp を重ねる、ARC 機首 000、自機は画面の横中央）: 前方 1.9km → 2km（距離だけの判定なら 5km）、真後ろ 1km → 5km（自機の位置「高め」なら 2km）、真横 800m → 右 2km / 左 1km（右は操作列の分だけ狭い）、前方 60m → 100m、前方 30m → 50m。REPLAY の帯（40dp）があると前方 1.9km → 5km。North Up: 北 3km → 5km、南 1km → 1km。
- 時刻の一括調整: 峠 8:00 → 展望台 8:30（締切 8:45）→ 道の駅 9:10 → 終点 11:00 で、先頭を 8:15 にすると 8:15 / 8:45（締切 9:00）/ 9:25 / 11:15。逆順にして先頭（終点）を 13:00 にすると 13:00 / 14:50 / 15:30 / 16:00。23:40 → 23:50 → 00:10 → 00:30 で先頭を 23:00 にすると 23:00 / 23:10 / 23:30 / 23:50。
- 標高プロファイル: 現在地 1000 m → A（1km 先、1100 m、次の WP）→ B（2km、標高なし）→ C（3km、1050 m）で、点は3つ（B は描かない）、現在地 → A は実線（マゼンタ）、A → C は破線。標高が 1000 m と 1010 m だけなら縦軸は 980〜1030 m（最小の幅 50 m）。
- PAN: 1 m = 0.1 px の North Up で指を右へ 100 px → 表示の中心は西へ 1000 m、下へ 100 px → 北へ 1000 m。ARC は始めた時点の機首方位（090）で向きを固定し、その後に機首方位が変わっても PAN の向きは 090 のまま。
- カウントダウン（JST）: 10:00 に 10:10 → +600、10:05 に 10:00 → −300、23:50 に 00:10 → +1200。
- NO FIX（10 秒設定）: 未測位 → NO FIX、10.000 秒 → NO FIX でない、10.001 秒 → NO FIX。
